Abstract—Unified multimodal generation covers discrete, continuous, and hybrid paradigms. Discrete approaches
with single-codebook visual tokenizers align naturally with text modeling but have limited representational capacity.
Continuous and hybrid approaches retain richer visual representations, but they model text and images in hetero-
geneous spaces with different training objectives, potentially introducing optimization conflicts between modalities
with misaligned representation spaces. These choices expose a central question: how to efficiently model high-
capacity visual representations alongside textual content in a shared optimization space within a single backbone.
We present Intern Lumina U2, to our knowledge the first diffusion language model to represent multi-codebook
visual tokens in a fully discrete space. Each visual position is represented by a group of codes from complemen-
tary codebooks, increasing its representational capacity while preserving compatibility with discrete text modeling.
At the input, the embeddings are concatenated at each position; at the output, a lightweight multi-codebook au-
toregressive head predicts the codes within each position sequentially, while the diffusion backbone processes all
positions in parallel. Built on the unified 4D representation of AToken, Intern Lumina U2 supports image, video, and
3D inputs within a single backbone and achieves leading performance among unified models in visual understand-
ing, image generation, and image editing. We further build a full-stack training, inference, and evaluation system
on both Ascend and NVIDIA platforms to verify the cross-platform effectiveness of our model. We also improve
the inference efficiency through a stability-aware sampling strategy, which combines confidence-plateau-guided
unmasking approach with drift-triggered cache refreshing mechanisms, accelerating image generation by 4.45×.

1. Introduction
Unified multimodal models integrate visual understanding and generation within a single
model (Chameleon Team, 2024; Deng et al., 2025; Tian et al., 2026).
However, architectural
sharing alone does not constitute complete unification, since understanding and generation may
still rely on separate representations and training objectives (Qiu et al., 2026).
To go beyond
architectural unification, we identify two principles for unifying understanding and generation more
comprehensively. First, text and visual content should be mapped into a shared optimization space
under a single objective. Although hybrid designs (Deng et al., 2025; Fan et al., 2025; Tian et al.,
2026) can achieve high visual fidelity by retaining continuous visual states and delegating synthesis
to a continuous decoder, they optimize visual generation with a continuous objective distinct from
the text objective and often adopt separate visual encoders for understanding and generation, leading
to optimization difficulties. Second, the generation process should respect the intrinsic structure
of each modality. Text follows a natural sequential order, whereas visual content has no canonical
generation order: each region depends on both its local neighborhood and long-range global context.
The generation process should therefore decode text sequentially while refining visual content in
parallel with bidirectional context.
Discrete masked diffusion provides a natural basis for satisfying the requirements above. It applies
a masked-prediction objective to discrete text and visual tokens, thereby optimizing both modalities
within a common discrete space. Under this formulation, each task is specified by partitioning the
token sequence into observed conditioning tokens and masked prediction targets. Understanding and
generation are thereby cast as distinct conditional queries to the same model, rather than as separate
tasks with task-specific objectives. Moreover, masked diffusion decodes tokens in parallel through
iterative refinement without imposing a fixed generation order (Nie et al., 2025; Chang et al., 2022;
Yang et al., 2025; Xin et al., 2025), allowing each spatial position to be refined with bidirectional
access to both local and global context. However, existing discrete unified models (Xin et al., 2025; Xie
et al., 2025a; Yang et al., 2025) remain limited in visual representation capacity, as single-codebook
tokenization compresses the visual information at each position into a single discrete code. Such a
compact representation is insufficient both for faithful reconstruction and for covering the full range
of visual tasks (Ma et al., 2025a). This motivates us to design a unified discrete framework that
carries a high-capacity visual representation in a shared space under a single training objective, while
modeling it efficiently with a unified backbone.
To this end, we present Intern Lumina U2, to our knowledge the first diffusion language model
that models multi-codebook visual states in a fully discrete space, with AToken (Lu et al., 2026) as the
visual tokenizer and LLaDA2.0 (Bie et al., 2025) as the backbone. Intern Lumina U2 encodes images,
videos, and 3D assets into a unified 4D code space and organizes these visual tokens together with
text tokens in a unified packed-sequence format, so that understanding and generation across all these
modalities are formulated over the same sequence representation and handled by a shared backbone.
Each visual position carries K complementary codes: independent embedding tables concatenated
at the input preserve codebook identity for efficient training, while a lightweight multi-codebook
autoregressive head models the dependencies among the codes within each position. Within this
shared representation, a multi-task masking mechanism assigns each task its own masking scheme,
so that understanding, generation, and editing across modalities are trained jointly under a single
objective. For image generation, a stability-aware inference strategy commits tokens at confidence
plateaus and refreshes the cache on hidden-state drift, achieving a 4.45× end-to-end speedup. We
further build the operators, parallelization strategies, and system adaptations for training, inference,
and evaluation on 1,024 Ascend 910B NPUs, with a smaller-scale NVIDIA reference run using the
same architecture and optimization recipe but a smaller training budget for cross-platform validation.

2. Related Work
We relate Intern Lumina U2 to four bodies of work: unified multimodal models, diffusion language
models, multi-codebook visual representations, and inference acceleration for masked diffusion. Ta-
ble 1 groups representative systems by backbone paradigm and summarizes their capability and de-
sign profile; Intern Lumina U2 is the only system in the comparison that combines image genera-
tion, perception across images, videos, and 3D assets, and masked-diffusion decoding over a multi-
codebook visual state. It represents all three visual input modalities with discrete backbone tokens
and generates images without a separate continuous diffusion or flow generator.
Unified multimodal understanding and generation.
One line of work models image generation as
discrete visual-token prediction within the backbone. Chameleon and Emu3 use a shared vocabulary
for text and visual codes under next-token prediction (Chameleon Team, 2024; Wang et al., 2026a),
whereas MMaDA and Lumina-DiMOO use masked prediction for both modalities (Yang et al., 2025;

Xin et al., 2025). Related discrete-generation designs include Janus and Janus-Pro, which decou-
ple the understanding encoder from the generation tokenizer (Wu et al., 2025b; Chen et al., 2025);
VAR and OneCAT, which use coarse-to-fine next-scale prediction (Tian et al., 2024; Li et al., 2026a);
and Emu3.5, which converts next-token image decoding to bidirectional parallel prediction for faster

diffusion or flow objective. Transfusion combines text next-token loss with image diffusion in one
Transformer (Zhou et al., 2025a), UniFluid models each position with a diffusion head (Fan et al.,

backbone and reconstructs images with a separate continuous generator. LLaDA2.0-Uni follows this
design: its backbone models text and visual tokens under a shared masked-prediction objective, while
a diffusion decoder synthesizes images conditioned on the predicted visual tokens (Bie et al., 2026).
Single-codebook discrete representations constrain the detail and semantics carried at each visual
position. Continuous and hybrid designs support richer image synthesis, but retain a continuous gen-
erative objective distinct from text-token classification, either within the backbone or in a separate
generator. Intern Lumina U2 instead uses multi-codebook discrete representations for image, video,
and 3D inputs, while training text prediction and image generation under a shared objective.
Diffusion language models.
LLaDA showed that masked diffusion language models trained from
scratch can match strong AR baselines, replacing left-to-right decoding with parallel iterative recov-
ery (Nie et al., 2025), and LLaDA2.0 converts a pretrained AR Mixture-of-Experts model into a block-
wise diffusion LM, preserving its knowledge while enabling parallel decoding (Bie et al., 2025). This
family has been extended to vision in several ways: LLaDA-V feeds features from a vision encoder into
the diffusion LM for understanding (You et al., 2026a), and LLaDA-o pairs discrete masked diffusion
for text with continuous diffusion for images (You et al., 2026b). Among the unified models discussed
above, MMaDA and Lumina-DiMOO extend masked prediction to both text and image tokens (Yang
et al., 2025; Xin et al., 2025), while LLaDA2.0-Uni adopts the converted LLaDA2.0 backbone with
block-wise masked prediction (Bie et al., 2026). Intern Lumina U2 also starts from LLaDA2.0-mini
and extends this family along two axes: the visual state becomes a multi-codebook visual token, and
the same model covers image, video, and 3D inputs.
Multi-codebook representations and depth decoding.
Residual and factorized quantization raise
the capacity of discrete visual states without lengthening the spatial grid: RQ-Transformer decodes
residual codes with a spatial-plus-depth Transformer (Lee et al., 2022), VILA-U brings multi-codebook
depth decoding into an AR unified model (Wu et al., 2025d), UniTok folds H×W×K codes into H×W
backbone positions (Ma et al., 2025a), and TokenBridge documents the dependence that is lost when
the codes of one position are predicted independently (Wang et al., 2025c). AToken supplies the
shared image/video/3D multi-codebook representation used here (Lu et al., 2026). These works
establish multi-codebook modeling in autoregressive systems. Intern Lumina U2 instead makes the
multi-codebook visual token the visual state of a masked-diffusion language model: the backbone
refines spatial positions in parallel, while the multi-codebook AR head models the dependence among
codes within each position (Section 3.4). This factorization keeps the backbone sequence length
independent of K without treating the codebooks as conditionally independent.

3. Model Architecture
3.1. Overview
As shown in Figure 3, Intern Lumina U2 is a masked diffusion language model that supports visual
understanding over images, videos, and 3D assets, as well as image generation and editing within a
unified model (Figure 3). To model all tasks with a single backbone and a shared training objective,
we represent every modality as discrete tokens. Specifically, visual inputs (images, videos, and 3D
assets) are first converted into visual tokens by a frozen visual tokenizer, AToken (Section 3.2), while

The resulting visual and text tokens, together with the target tokens (either a text answer or a target
image, represented as the mask tokens), are arranged into a single sequence. The MoE diffusion
LLM (Section 3.3) processes this sequence and predicts the masked tokens in a modality-specific
manner. Masked text tokens are predicted by a text head and generated block by block. In contrast,
masked visual tokens are predicted by a multi-codebook AR head (Section 3.4): each visual token
contains K=8 discrete codes, and the head predicts visual tokens at different positions in parallel
while generating the discrete codes within each token sequentially. Finally, the AToken decoder maps
the predicted visual codes back to pixels.
3.2. Unified Visual Tokenizer
The visual tokenizer serves as the interface between raw visual data (images, videos, and 3D assets)
and the model, and therefore constrains both generation and understanding. As discussed in the
previous section, Intern Lumina U2 places two requirements on its visual tokenizer: (1) it must pro-
duce discrete visual tokens that can be modeled in the same way as text tokens, so that all tasks can
share a single masked-diffusion objective; and (2) these tokens must preserve both the low-level detail
for generation and the high-level semantics needed for understanding. However, existing tokenizers
are typically specialized for either low-level detail or high-level semantics. For example, tokenizers
7

trained for reconstruction, such as VQGAN (Esser et al., 2021), keep fine detail but are not trained
to align with language, whereas semantic encoders such as SigLIP (Zhai et al., 2023) align well with
text but are not trained to reconstruct pixels.
We therefore adopt AToken (Lu et al., 2026) as the visual tokenizer. AToken is initialized from a
pretrained SigLIP2 encoder (Tschannen et al., 2025) and trained jointly for reconstruction and under-
standing. As a result, its tokens carry semantic structure while still supporting faithful reconstruction.
In addition, AToken encodes images, videos, and 3D assets into a shared 4D latent space, so that a
single tokenizer serves all three modalities. We use its discrete configuration, which quantizes each
location of the latent grid with finite scalar quantization (FSQ) (Mentzer et al., 2024) over K=8 code-
books. Each codebook is a vocabulary of 4096 entries, and a code is the index of one entry, so each
location is represented by K codes c = (c1, . . . , cK), one per codebook. We call such a location a visual
position and its K codes a visual token (Figure 3). Compared with a single code per position, the eight
codes give the representation more capacity for fine visual detail. The tokenizer is kept frozen during
training, and the grid shapes, flattening orders, and structural tokens are listed in Appendix B.
3.3. Backbone
We build our backbone upon LLaDA2.0-mini (Bie et al., 2025), a masked diffusion language model
obtained by converting a pretrained autoregressive mixture-of-experts (MoE) language model (Ling
Team, 2025) into a block diffusion model. It has 16B parameters in total, of which 1.4B are activated
per token. Among its 20 Transformer layers, the first employs a dense feed-forward network, while
the remaining 19 are MoE layers. Each MoE layer consists of 256 routed experts and a single shared
expert, with 8 routed experts activated per token. LLaDA2.0-mini is a language model which generates
text via block diffusion: a sequence is divided into blocks of consecutive tokens, and each block is
denoised by masked diffusion conditioned on all preceding blocks. Accordingly, it generates text
block by block at inference: the masked tokens within the current block are predicted in parallel and
iteratively refined over several denoising steps, while the key–value cache of previously completed
blocks is reused. Since LLaDA2.0-mini already performs masked diffusion over text, we can directly
inherit its language capabilities without an additional autoregressive-to-diffusion conversion (Gong
et al., 2025; Ye et al., 2025a; Bie et al., 2025).
We introduce two modifications to LLaDA2.0-mini while keeping all other components unchanged,
including the Transformer layers, the text embedding table, the text head, and the <|mask|> token.
First, we add the visual input and output interfaces described in Section 3.4, which account for 0.65B
parameters. Second, we replace the attention mask with our proposed task-aware attention mask.
LLaDA2.0-mini was trained exclusively on text with a block-wise attention mask, whereas our Intern
Lumina U2 also contains visual conditions and visual answers. We therefore design a task-aware
attention mask that controls attention among these segments according to the task (Section 3.5). It
is worthy to mention that we retain the native positional encoding (e.g. 1D RoPE (Su et al., 2024)) of
the backbone for visual tokens, rather than introducing a dedicated 2D or 3D scheme, which preserves
the positional prior learned in pretraining. Since 1D RoPE does not explicitly encode spatial structure,
the spatial or spatio-temporal layout of each visual input is instead indicated by structural delimiter
tokens inserted into the sequence (Appendix B). In this way, images, videos, and 3D assets are all
represented in the same 1D token sequence as text.

3.5. Unified Data Format with Data Packing
Having specified the representation of a single visual position, we now describe the organization of
complete samples into training sequences. All tasks, from text-only dialogue to image generation
and editing, share a unified packed sequence format. Moreover, to determine the attention mask and
calculate loss, each token in this format is annotated with five metadata fields: type (text condition,
visual condition, structural token, text answer, or visual answer), turn index, noise state (clean or
noisy), block index, and position ID.

Every sample is first formatted as a dialogue between
a user and an assistant, in which each turn consists of a user message and the assistant’s reply to it.

4. Data Construction
To train Intern Lumina U2, we construct a comprehensive and diverse training corpus and organize
it in a consistent format. For diversity, our training data span six categories: image understanding,
video understanding, 3D understanding, text-to-image generation, image editing, and text-only data.
Each category is built from dedicated sources and filtered with category-specific quality checks. For
consistency, we convert all samples into a common dialogue format. The converted samples are then
mixed in stage-specific proportions for the training stages described in Section 5.

4.3. Multimodal Understanding Data
Image understanding is the largest of the three understanding categories. Its data are drawn mainly
from the public instruction-tuning collection LLaVA-OneVision (Li et al., 2025) and the private instruc-
tion data of InternVL (Wang et al., 2025a), which includes image captioning, document understand-
ing, and chart data. To balance the mixture across skills, we organize these data by capability rather
than by source dataset. This yields three capability groups: perception (image captioning, general vi-
sual question answering, grounding, and counting), text-rich image understanding (OCR, documents,
charts, and GUI or web screenshots), and knowledge-intensive reasoning (science questions and math-
ematics).
The video and 3D understanding data are limited in scale, but are constructed in the same man-
ner as the image understanding data. The video data comprise captioning and question-answering
datasets built on public video corpora, together with temporal reasoning datasets covering event or-
dering, counting, and temporal localization tasks (see Appendix C for the full list of sources). The 3D
data consist of object-centric assets paired with captions and question-answering annotations, drawn
from Objaverse (Deitke et al., 2023) (with Cap3D captions (Luo et al., 2023)), GAPartNet (Geng et al.,
2023), and Sketchfab (Sketchfab, 2026).
4.4. Text-to-Image Data
Text-to-image generation requires training images that span a broad range of concepts and domains,
contain rich details, exhibit high aesthetic quality, and are accurately described by their captions.
These requirements fall into three aspects: concept coverage, caption quality, and image quality. We
therefore organize the construction of the text-to-image corpus into three steps, each addressing one
aspect: (i) source coverage and domain-specific expansion, which broaden the range of concepts and
15


Intern Lumina U2: A Multi-Codebook Diffusion Large Language Model for Omni-Visual Understanding and Image Generation
domains; (ii) caption reconstruction and prompt expansion, which improve caption quality; and (iii)
filtering, deduplication, and balancing, which raise image quality and reduce redundancy.
Source coverage and domain-specific expansion.
To cover a broad range of concepts, we draw
on three types of sources: (i) web-crawled image–text pairs for the 2562 training stage; (ii) curated
real-world photographs with captions in both English and Chinese; and (iii) synthetic images gener-
ated by existing text-to-image models, with the corresponding generation prompts used as captions.
Nevertheless, general-purpose sources alone cannot ensure comprehensive coverage: an analysis of
generated samples revealed three weak areas, namely Chinese text rendering, scientific illustrations
(including physics diagrams), and text-heavy graphic designs. Rather than scaling up all sources, we
construct a small dedicated dataset for each weak area and upweight it individually.
Caption reconstruction and prompt expansion.
Because the prompt is the only conditioning
signal in text-to-image generation, the quality of training prompts is critical. We construct three types
of prompts: original prompts, recaptioned prompts, and reasoning-augmented prompts. Original
prompts and alt-texts are retained only when they describe the image adequately.
In addition,
InternVL3.5-30B-A3B (Wang et al., 2025a) generates both a long-form and a short-form recaptioned
prompt for images whose original captions are missing, mismatched, or too generic. Both recaptioned
prompts describe the subjects, attributes, relations, composition, style, and visible text of the image
at different descriptive granularity. During training, the prompt of each sample is randomly drawn
from its original prompt and two recaptioned prompts. Finally, for a subset of samples, we construct
reasoning-augmented prompts by inserting a reasoning trace, enclosed in <think> tags, before the
target image. Within this trace, the prompt is expanded into an explicit description of the intended
image. These samples are used to train the thinking mode for image generation.
Filtering, deduplication, and balancing.
This step consists of three stages: rule-based filtering and
deduplication, model-based quality filtering, and data balancing. In the first stage, every sample must
pass validity checks that require a decodable image, a minimum side length, and a non-empty prompt
with the length limit. In the second stage, every sample is scored by a vision-language judge (Qwen3-
VL-30B-A3B-Instruct (Bai et al., 2025a)) for aesthetics, image quality, structural richness, and prompt
following under the UniPercep protocol. Filtering then applies three rules in order, discarding samples
with illegible or missing required text, samples below the prompt-following threshold, and samples
outside the top range of aesthetic scores; the thresholds and filtering statistics are given in Appendix C.
In the final stage, we balance the remaining data by adjusting the sampling multiplicity of each subset
according to its content domain, language, and caption complexity.
4.5. Image Editing Data
Image editing is an image-to-image (I2I) task in which the model generates a target image conditioned
on one or more source images with an editing instruction. A valid editing sample must therefore
satisfy two requirements: the target image reflects the requested change, while leaving unmentioned
subjects, identities, layouts, and backgrounds unchanged. Our editing data consist of two parts: public
datasets, namely OmniEdit (Wei et al., 2025), ImgEdit (Ye et al., 2025b), SEED-Data-Edit (Ge et al.,
2024), X2Edit (Ma et al., 2026a), and additional in-house synthetic data. The resulting editing corpus
covers ten edit types: addition, removal, replacement, adjustment, extraction, background change,
style transfer, hybrid editing, action editing, and in-image text rendering. Quality control follows
directly from this definition, supplemented by a check on image quality. Specifically, for each sample
16


Intern Lumina U2: A Multi-Codebook Diffusion Large Language Model for Omni-Visual Understanding and Image Generation
we verify that (i) the target differs visibly from the source; (ii) the observed change matches the
instruction; (iii) regions not referenced by the instruction remain consistent between the source and
target images; and (iv) the target image is of adequate visual quality.
5. Training Strategy
The Intern Lumina U2 training pipeline contains five stages that progressively increase the length
of the visual context, broaden the distribution of tasks, and expand the range of supported visual
modalities. At the start of training, the MoE backbone, text embedding table, and text prediction
head are initialized from LLaDA2.0-mini (Bie et al., 2025). The visual embedding tables, visual input
projection, and multi-codebook AR head are trained from scratch, while the AToken tokenizer remains
frozen. Each stage is initialized from the preceding checkpoint, and all stages use the unified objective
of Section 3.6. The same training strategy is applied on two hardware platforms: the Huawei Ascend
NPU run as the primary model, while the NVIDIA GPU run as a cross-platform recipe reference.
5.1. Training Stages
Stage 1: Vision–Language Alignment.
Stage 1 aligns the random initialized visual modules (the
visual embedding tables, visual input projection, and multi-codebook AR head) with the pretrained
language backbone. The model is trained at 256 × 256 resolution on a mixture of text-only, image
captioning, and text-to-image data. Image captioning and text-to-image data provide supervision for
image-to-text and text-to-image generation, respectively, while text-only data preserve the language
capabilities of the backbone. Through these two complementary pathways, the model establishes
an initial vision-language alignment and acquires preliminary image understanding and generation
capabilities, which are further developed in the subsequent stages.
Stage 2: Perception Pretraining.
Stage 2 increases the training resolution to 512 × 512 and broad-
ens the image understanding data to cover more demanding tasks, including OCR, grounding, doc-
ument understanding, and chart understanding. The higher resolution provides the spatial detail
required for fine-grained recognition and localization, particularly in text-rich documents and charts.
Consequently, the model acquires fine-grained perception capabilities, which are essential for the
more complex visual tasks introduced in later stages.
Stage 3: Omni-Visual Mid-Training I.
Stages 1 and 2 establish the basic vision–language align-
ment and the fundamental visual capabilities. The next two stages bring all visual modalities and
capabilities from understanding to generation and editing into training. The first of them increases
the training resolution to 1024 × 1024 without introducing new modalities or tasks. Empirically, we
find that expanding modality coverage simultaneously with the resolution increase leads to severe
degradation of previously acquired capabilities. We therefore use this stage to isolate the resolution
transition: no new modalities or tasks are introduced while the model adapts its existing perception
and generation capabilities to 1024 × 1024, allowing training to stabilize before modality coverage is
expanded.
Stage 4: Omni-Visual Mid-Training II.
Once training at 1024×1024 has stabilized, the second stage
of omni-visual mid-training broadens the training recipe by incorporating data for image editing, video
understanding, and 3D understanding. The model learns these new tasks through the same visual
interface and unified objective as in earlier stages. Image and text data from the preceding stages
17


Intern Lumina U2: A Multi-Codebook Diffusion Large Language Model for Omni-Visual Understanding and Image Generation
remain in the mixture so that the model retains its existing capabilities. The two stages of omni-visual
mid-training share a combined token budget, which amounts to 500B tokens on the Ascend run and
200B tokens on the NVIDIA run, as reported in Table 3.
Stage 5: Supervised Fine-Tuning for Instruction Following.
This stage fine-tunes the model at
1024 × 1024 on a high-quality instruction-tuning dataset curated from the previous data sources and
reformatted for instruction following. The dataset covers text-to-image generation, image editing,
omni-visual understanding (images, videos, and 3D assets), and text-only question answering. Fine-
tuning on these data aligns the capabilities acquired in earlier stages with instruction-following be-
havior, enabling the model to understand task instructions and produce the corresponding outputs.
The quality-filtered data further improve the overall performance of the model. We also use a lower
learning rate than in previous stages, so that the model gradually adapts to the instruction-following
distribution while retaining the knowledge and generation quality it has already developed.

5.3. Optimization and Parallel Training
Optimizer.
We optimize the trainable 2D and 3D weight matrices, including the attention, feed-
forward, expert, and projection weights, with Muon (Jordan et al., 2024), which has been shown to
match AdamW with substantially fewer training tokens (Liu et al., 2025a) and to remain stable on
trillion-parameter MoE models (Kimi Team, 2025, 2026). For the query, key, and value projections, we
use the per-head variant of Kimi K3 (Kimi Team, 2026), which orthogonalizes the update of each atten-
tion head separately. All other trainable parameters, namely the embedding layers, one-dimensional
parameters such as norms and biases, and the text output head and the per-codebook output classifiers,
are optimized with AdamW (Loshchilov and Hutter, 2019) using fixed betas (0.9, 0.999) and ϵ = 10−8.
Stage-specific learning rates, weight decay, warm-up, gradient clipping, and Muon hyperparameters
are reported in Table 3.

stages. The data collator concatenates training samples until a predefined packing length limit is

a single sample. The data collator also records the cumulative sequence lengths of the packed samples,
which mark the sample boundaries to confine attention and loss computation to each sample. There-
fore, this packing strategy reduces sequence-level padding overhead while retaining sample-internal
padding, without altering the objective for any individual sample. On both platforms, we use FSDP2

Text decoding.
We generate text with block diffusion (Arriola et al., 2025; Bie et al., 2025), which
extends a fully decoded prefix from left to right while denoising the tokens within each appended block

at the <EOA> token, enabling variable-length outputs; and (ii) the key–value cache of the completed
prefix can be reused when decoding the next block.

6.2. Inference Acceleration
Since image sampling is computationally expensive, we apply training-free acceleration at two levels
of the sampler: (i) reducing the cost of each step by reusing cached intermediate states whose inputs
remain stable, and (ii) adapting the remasking decisions when a position reaches a temporal plateau.
The following subsections describe these mechanisms and evaluate their quality–latency trade-off.
6.2.1. Batching and Cache-Aware Reuse
Recent masked-diffusion decoders reduce the repeated computation across refinement steps by
reusing the intermediate hidden representations or key-value caches. Fast-dLLM (Wu et al., 2026a)
and dKV-Cache (Ma et al., 2025b) introduce approximate cache reuse for bidirectional diffusion
decoders, and dLLM-Cache (Liu et al., 2026) selectively refreshes cached response positions based
on the V-verify score. To reduce redundant computation, our inference implementation combines
three complementary mechanisms for batch sharing and cache reuse.
First, the conditional and
unconditional branches of classifier-free guidance (CFG) are evaluated together in one batch, which
shares the backbone computation between the two branches. Second, the multi-codebook AR head
caches key-value states as it predicts the K codes at each visual position, avoiding recomputation of
the previously generated code prefix. Third, the backbone reuses cached hidden states at positions
with unchanged codes.
Together, these mechanisms reduce repeated computation in the CFG
branches, the AR head’s code prefix, and backbone processing at positions where codes remain
unchanged, while preserving the full K-step sequential prediction within each visual position.
Reusing cached backbone states requires a criterion for detecting stale cache entries. For this
purpose, we use a drift test adapted from the V-verify score of dLLM-Cache (Liu et al., 2026), to
decide when the backbone cache must be refreshed. At step t, let St denote the set of positions
recomputed due to the change of input codes or the selection by the refresh schedule. Let ht,i,r denote
the conditional hidden-state component r ∈{1, . . . , d} at position i, where d is the hidden-state width.

We ablate the two plateau controls of PHV (Section 6.2.2), the
change threshold δp and the confidence floor fp, on a 6×6 grid with 553 prompts per cell (Figure 11);
the remaining controls are fixed at their default values. The two parameters act as a serial gate rather
than as independent controls: δp determines which positions become eligible for early commitment,
and fp only limits how many of the eligible positions commit. As a result, the influence of fp on
the number of refinement steps increases by 17.6× from the strictest to the loosest δp, since at small
δp the flatness test rarely fires and fp has little effect. The selected quality-first setting (δp=0.18,
fp=0.005) lies on the speed–quality frontier, reaching GenEval 89.3 at 35.9 s per image.

8. Conclusion
We have presented Intern Lumina U2, to our knowledge the first unified understanding-and-
generation diffusion language model that models multi-codebook visual states in a fully discrete
space and extends visual understanding across images, videos, and 3D assets.
Its visual input
interface preserves codebook identity by assigning each codebook an independent embedding
table and merging the resulting embeddings into a single backbone token through concatenation
and projection. Its visual output interface uses a multi-codebook AR head to predict the codes at
each visual position autoregressively along the codebook dimension, while masked diffusion refines
all spatial positions in parallel.
Ablation studies confirm the contribution of both design choices.
Codebook-specific input embeddings improve next-code top-1 accuracy, with the largest gains on
later codebooks. The multi-codebook AR head captures inter-code dependencies and achieves the
best results on all four generation benchmarks, with the most pronounced gains in counting, position,
and attribute binding.
At the system level, the primary model is trained on 1,024 Huawei Ascend 910B NPUs and provides
the main reported results. A reference model, trained independently on NVIDIA GPUs with the same
architecture and optimization recipe but a smaller training budget, is used to assess cross-platform
consistency. In addition, our proposed temporal-stability-guided sampling strategy reduces image
generation latency by 4.45× under the same evaluation protocol without degrading generation quality.
Overall, the results on omni-visual understanding, image generation, image editing, and physically
grounded scientific-diagram generation demonstrate the potential of fully discrete diffusion language
modeling to unify broad visual understanding and high-quality generation within a single framework.
Despite these advances, several limitations remain. First, the multi-codebook autoregressive head
introduces additional decoding overhead, and high-resolution generation produces long visual se-
quences. Second, the current system covers image generation and editing, but has not yet been
extended to video or 3D generation. In future work, we plan to extend generation to videos and
3D assets, explore more tightly interleaved multimodal generation, investigate post-training with re-

A.2. Special tokens
Table 18 lists the corresponding special tokens. Text-related tokens contains 157,184 tokens from
LLaDA2.0 vocabulary and are embedded with the corresponding text embedding table. Visual-related
tokens are stored in each of the K visual embedding tables, which have 5010 entries each: the first
4096 entries hold the codebook codes, and the entries after them hold the visual mask token and the
delimiter tokens that mark the end of an image row, a video row or frame, and a 3D row or layer.
Since a packed sequence is stored as an [L, K] tensor with one column per codebook, each text or
structural token is written into all K columns, and the model reads it from the first column only.

Data validation.
Before training, the annotations and sequence lengths of each data mixture are
precomputed offline, and sources unchanged from a previous mixture are reused after their first sam-
ple is checked for consistency, while changed or new sources are processed again. The precomputed
data pass four checks before use: (i) the numbers of sources and samples match the mixture def-
inition; (ii) randomly drawn samples are non-empty and can be parsed; (iii) on a random subset,
recomputed sequence lengths equal the stored ones; and (iv) a random subset can be converted into
packed training sequences without error.
Text-to-image quality filtering.
As described in Section 4, the vision-language judge Qwen3-VL-
30B-A3B-Instruct scores every image under the UniPercep protocol on four axes, each ranging from 0
to 100: aesthetics (composition, color and lighting, and artistic expression), image quality (sharpness,
artifacts, and anatomical errors), structural richness, and prompt following (subject, count, attributes,
scene, style, and text requirements). Under this protocol, the judge answers each axis with a two-
letter code for one of four score bands (0–25, 26–50, 51–75, and 76–100), which avoids its bias
toward particular digits, and the continuous score is the expectation over the bands weighted by
the predicted code probabilities. Filtering then applies three rules in order: images with illegible or
missing required text are discarded, images with a prompt-following score below 60 are discarded,
and among the remaining images only those in the global top 70% by aesthetic score, a threshold of
about 74, are kept. Table 22 reports the number of images removed by each rule for the two curated

D. Ascend Adaptation Details
Intern Lumina U2 is trained, evaluated, and served entirely on Ascend NPUs. Porting the code from
GPUs requires changes in three respects, since the available operators, the interface semantics of the
fused kernels, and the memory capacity of each NPU all differ from those of the GPU software stack,
and the following paragraphs describe how each difference is handled.
Execution path.
Every entry point imports torch_npu.contrib.transfer_to_npu before any model
code. This remaps torch.cuda onto the NPU runtime, so no ’cuda’ literal in the model files has to be
rewritten. Each rank is given its own HF_MODULES_CACHE directory; otherwise the ranks shar-
ing a node write the same dynamically imported module files at the same time. The AToken decoder
46


Intern Lumina U2: A Multi-Codebook Diffusion Large Language Model for Omni-Visual Understanding and Image Generation
ships with a flash_attn dependency that does not exist on this platform, so its attention modules are
rebuilt on the native kernels. That rebuild covers the image-decoding path; the understanding and
text paths never reach that code.
Fused mixture-of-experts.
We rebuild the fused MoE path on torch_npu.npu_grouped_matmul,
since the fused path of the GPU stack is a Triton kernel. The forward pass permutes tokens into ex-
pert order with npu_moe_token_permute, then runs one grouped matrix multiplication against the
merged first projection, npu_swiglu, and a second grouped matrix multiplication against the second
projection. The routing weights are applied as the result is unpermuted. The kernel provides no
backward pass, so we write one as an explicit autograd function. It uses two further grouped ma-
trix multiplications: one against the transposed weights for the input gradient, and one against the
transposed activations, under a different grouping mode, for the weight gradient. An expert-parallel
variant wraps the same kernel in all-to-all dispatch and combine.
Attention kernel semantics.
Attention uses torch_npu.npu_fusion_attention in the BNSD layout,
with the TND layout and actual_seq_qlen available for variable-length batches. Two interface details
change results silently, and both are handled explicitly. First, the mask polarity is inverted relative
to the SDPA convention: the kernel reads True as masked, so the additive 4D mask is converted and
negated rather than passed through. Second, the variable-length interface ignores atten_mask and
behaves as if no mask had been supplied, so it can express only full bidirectional attention or one
template shared by every segment. The task-aware mask of Section 3.5 gives each packed segment
its own pattern, so packed training uses the dense path, where the mask reaches the kernel exactly as
specified.
Memory.
Per-NPU memory is the binding constraint of the training configuration,
which
makes activation allocation a first-order target rather than a detail absorbed by spare capacity.

The data-parallel shard group size is 24 or 32 depending on the size of the job, which trades

Gradient checkpointing is
enabled on the backbone blocks. The cache-release interval is 20 steps rather than 100, which keeps
fragmentation from accumulating across the long tail of packed sequence lengths. Together they
lower peak memory and raise the longest sequence one NPU can hold, which is the quantity that sets
training efficiency at fixed hardware.
Inference.
A trained checkpoint stores the 256 experts of a layer as one stacked tensor. The platform
provides a grouped matrix-multiplication kernel, so Ascend inference loads that layout directly and
serves the training-time weights unchanged. The GPU path has no such kernel: it must first split the
stacked tensor into per-expert weights, which costs a conversion pass and a second copy of the expert
parameters.
