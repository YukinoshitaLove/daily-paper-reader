ABSTRACT
Language models switch tasks from demonstrations, but vision still often relies on separate systems for restoration,
editing, and stylization. A before–after example offers a shared instruction only if the transferable change can be
separated from the scene that demonstrates it. We introduce CROSSPAIR, which adapts a pretrained multimodal image
editor to transfer diverse transformations from one exemplar pair. Exemplar-before, exemplar-after, and query images
take fixed roles in its native VLM and VAE pathways: the VLM extracts operation semantics, while the VAE retains
fine appearance and structure. A training-only, change-aware DINOv3 objective aligns feature-change directions across
content-distinct scenes, guiding the output to follow the demonstrated relation without an inference-time encoder. We
construct TRANSFORM-360K by grouping filtered pairs from conditional representations, restoration, editing, virtual
try-on, and stylization under shared transformations. On Relation252K-derived seen and held-out transformations,
CROSSPAIR improves target agreement and edit-direction similarity over released systems. Ablations show that the
semantic and visual exemplar routes are complementary and that DINO relation alignment further strengthens transfer;
TRANSFORM-360K training also improves aggregate held-out-operation scores.
Keywords: Visual in-context learning; Image editing; Visual analogy; Exemplar-guided transformation

Introduction
Many visual transformations are easier to show than to name:
phrases such as “make it ceramic” or “change the viewpoint”
underspecify texture, geometry, and what should remain un-
touched. A before–after pair reveals both the change and the
invariant content, offering a common task interface across
conditional generation, restoration, editing, try-on, and styl-
ization. The challenge is to infer that rule from one demon-
stration and apply it to a different scene.
The demonstrated change is entangled with its reference
scene, while a content-distinct query must remain recogniz-
able. Visual prompting and exemplar-based editing establish
pair-conditioned transfer (Bar et al., 2022; Sun et al., 2023;
Chen et al., 2025; Gong et al., 2025; Manor et al., 2026;
Chen et al., 2026b); CROSSPAIR coordinates semantic inter-
pretation, fine-grained visual evidence, and explicit relation
agreement inside a pretrained multimodal editor. Given one
reference pair and a content-disjoint query, it solves the
visual analogy xr : yr :: xq : yq, where only (xr,yr,xq) are
visible at inference. The pair supplies visual evidence, com-
plemented by record-specific text that can name the edit.
CROSSPAIR realizes this interface through role-ordered
dual-space exemplar conditioning. The reference-before,
reference-after, and query images enter a semantic VLM
pathway and a visual VAE pathway in the same order. The
VLM interprets the triplet to infer what operation should
transfer, whereas the VAE preserves the colors, textures,
shapes, and local structures needed to reproduce it. Their
fusion combines semantic abstraction with fine-grained vi-
sual evidence, while relation supervision encourages the
predicted change to follow the demonstrated one.
Conditioning alone, however, does not explicitly require
the predicted change to agree with the demonstrated one.
We therefore introduce a training-only, change-aware DI-
NOv3 objective (Siméoni et al., 2025). It localizes informa-
tive changes independently inside the reference and query
scenes, aggregates their patchwise feature displacements
into relation directions, and aligns those directions across
content. This formulation avoids assuming correspondence
between unrelated scenes and regularizes the demonstrated
relation without directly matching prediction and target fea-
tures. The complete DINO branch is removed after training.
Finally, we introduce the TRANSFORM-360K corpus,
built through six source-specific construction pipelines, hy-
brid semantic and automatic filtering, and fine-grained re-
lation grouping. It contains approximately 90K four-image
training records (360K record-level image occurrences)

Related Work
2.1
Diffusion-Based Image Editing
Text-guided editing (Hertz et al., 2022; Brooks et al., 2023;
Geng et al., 2024; Huang et al., 2024) and spatial con-
trols (Couairon et al., 2023; Zhang et al., 2023) expose
language or auxiliary maps as task specifications. Reference-
conditioned methods (Yang et al., 2023; Chen et al., 2024;
Ye et al., 2023) transfer appearance or object content. A
before–after exemplar instead demonstrates a change. Qwen-
Image-Edit (Wu et al., 2025) already offers semantic VLM
and reconstructive VAE conditioning; CROSSPAIR assigns
exemplar and query roles in these existing routes and uses a
frozen DINOv3 branch only during training.
2.2
Visual In-Context Editing
Image analogies (Hertzmann et al., 2001), Visual Prompt-
ing (Bar et al., 2022), Painter (Wang et al., 2023), and Im-
ageBrush (Sun et al., 2023) established visual demonstration
as a task interface. PairEdit (Lu et al., 2025), Edit Trans-
fer (Chen et al., 2025), RelationAdapter (Gong et al., 2025),
LoRWeB (Manor et al., 2026), VIRAL (Li et al., 2026), and
EditTransfer++ (Chen et al., 2026b) all address exemplar-
based editing; Textualize Visual Prompt (Xu et al., 2025)
translates pair evidence into text through a diffusion bridge,
while EditCLIP (Wang et al., 2025a) learns pair-level edit
representations. Thus one-pair transfer itself is established.
Compared with per-exemplar adaptation and dedicated re-
lation encoders, our contribution is a fixed triplet interface
in the pretrained editor’s two native pathways plus change-
weighted relation regularization with no inference-time aux-
iliary encoder. Table 3 studies the proposed components
within a matched backbone.

3.2
One-Pair Inference, Cross-Pair Supervision
Let T denote a transformation. A training item contains
one reference pair (xr,yr), where yr = T (xr), and one query
pair (xq,yq), where yq = T (xq). At inference, the model
receives (xr,yr,xq) and optional text p, and predicts
ˆyq = Gθ(xr,yr,xq; p).
(4)
There is one demonstration pair per forward pass and at
inference. However, the aligned query target makes the
training unit a pair of pairs. We call the setting one-pair
prompting, not single-pair supervision; the latter describes
methods that self-supervise from (xr,yr) alone (Chen et al.,
2026a). The evaluated Relation252K records combine a role
instruction with a concrete edit description when available;
one such description requests teeth alignment and whitening.
Appendix C.4 records the serialized prompt.
The central modeling decision is how to expose the ex-
emplar. We represent the same ordered triplet in two com-
plementary spaces: a fine-grained VAE condition Cvae and
a semantic VLM condition Cvlm. They are not competing
transformation encoders; together they preserve what the
change looks like and explain what operation it expresses.

3.5
TRANSFORM-360K
Transformation canonicalization.
We do not pool
heterogeneous before–after images under dataset names or
broad task labels. Each candidate is normalized as (x,y,g),
where g records the finest verifiable operation and its
direction. For style and try-on, g is the style or garment iden-
tity (Wang et al., 2025b; Gao et al., 2026; Shen et al., 2025);
for conditional representations it is an ordered modality
mapping (e.g., RGB→depth is distinct from depth→RGB);
for restoration it is the degradation task; and for spatial edits
it is a discretized viewpoint, distance, or rotation delta (Xiao
et al., 2026). The six construction streams instantiate these
keys from style pairs, RGB/edge/depth/normal/pose/line-
art/mask/box/segmentation
mappings,
garment
trans-
fers, low-level restoration, reference-driven perception/
generation, and controlled geometry.
Pair validation.
Every pair must pass common checks
for readability, resolution, duplicate status, and a non-trivial
but bounded visual change. An MLLM then verifies that the
claimed operation is visible, non-target content remains con-
sistent, and artifacts do not explain the difference. Stream-
specific predicates make this test concrete: style pairs reject
content drift or residual target style in the source; condition
maps reject empty or invalid structure; try-on pairs require
the same garment on different people; restoration pairs re-
tain the same scene and declared degradation; and spatial
pairs must realize the keyed geometric delta. Conventional
image and perceptual statistics screen obvious failures be-
fore the semantic audit.
Construction audit.
Candidates pass full decoding
and geometry preflight before relation assembly. In one
captioned-source pass, 67,271 of 72,273 records survive
these checks; a separate MegaStyle semantic audit retains
7,552 of 12,450 candidate pairs when both images pass its
consistency test. The retained pairs then enter operation-
specific validation and cross-content pairing, with the
detailed source inventory in Appendix B.

Cross-pair record formation.
Within each key g, we re-
quire distinct content/scene identities, reject self- or shared-
scene pairings, and sample one pair as (xr,yr) and another
as (xq,yq). We then balance relation frequency and source

grained relations, compared with the 200+ transformation
groups in Relation252K. The supplementary material pro-
vides source inventories, the serialized record schema, filter-

The frozen manifest has 91,010

4
Experiments
4.1
Evaluation Setup
Training-data protocol and fairness.
We separate the
core method comparison from the dataset-scaling study.
RelationAdapter (Gong et al., 2025) is trained on Rela-
tion252K, whereas the released LoRWeB model (Manor
et al., 2026) uses Relation252K together with additional
training data. Our primary CROSSPAIR model uses a 265K
training mixture derived from Relation252K, and the
TRANSFORM-360K checkpoint is evaluated separately. A
second checkpoint trained on TRANSFORM-360K is added
only to the OOD panel.
Baselines and inference controls.
We compare with the
publicly available LoRWeB (Manor et al., 2026) and Re-
lationAdapter (Gong et al., 2025) systems, together with
Qwen-Image-Edit-2511 (Wu et al., 2025). All methods
receive the same held-out record and one exemplar pair;
extracted outputs are resized to the same metric resolu-
tion. Released systems retain their native inference proce-
dures, so this is a complete-system comparison rather than
a mechanism-matched backbone study.
Evaluation protocol.
For in-domain, we test 219 seen
transformation groups with five held-out queries each.
For out-of-domain, we augment Relation252K’s released
unseen-task split with 150 additional cases from diverse
editing families; unseen denotes held-out transformation
groups, not merely new images within a seen group. The
resulting protocol comprises 1,095 seen-task queries and
450 OOD queries; query records are excluded from their
corresponding training groups and cannot serve as their own
demonstrations. We report CLIP-I against the ground-truth
target and query source, LPIPS against the target, and
CLIP directional similarity. For GPT-5.5 evaluation, the
judge first infers the transformation from the exemplar pair
and then ranks the anonymized candidate outputs (four
in-domain and five OOD). The overall ranking prioritizes
transformation faithfulness, followed by query-content
preservation and visual quality; two diagnostic rankings
isolate the first two criteria. Neither the ground-truth target
nor method identities are shown to the judge. We report
the single-judge rankings as diagnostic preferences and the
mixed-family CLIP/LPIPS scores as benchmark averages.

the same interface with a broader operation inventory.

5
Conclusion
CROSSPAIR turns a pretrained editor into a one-pair trans-
formation learner through role-ordered VLM/VAE condi-
tioning and training-only DINOv3 relation alignment. The
complementary pathways carry semantic and visual evi-
dence, while relation supervision strengthens transfer across
content-distinct scenes without an added inference-time
module. The TRANSFORM-360K checkpoint broadens the
range of held-out operations addressed by the same inter-
face. Together, the method and corpus support a shared
demonstration-based interface for diverse visual transforma-
tions.
Broader impacts.
Exemplar-guided editing can transfer
harmful changes as readily as beneficial ones, while syn-
thetic and web-derived examples may carry visual biases.
Evaluation of both transformation transfer and retained
query content should accompany deployment.

A
Evaluation Scope
Comparison design.
One-pair transfer is established in
prior work; CrossPair’s contribution is its role-ordered use
of the editor’s native conditioning paths and training-only
DINO relation alignment. We compare released systems as
complete pipelines and use the matched ablation to examine
CrossPair’s components. The Relation252K-derived model
is the core method comparison; the Transform-360K check-
point assesses the combined effect of its larger, differently
composed training corpus.
Metric interpretation.
CLIP and LPIPS results are query-
level micro averages across task families, while GPT-5.5
provides one ranking per query. Source similarity and the
content ranking complement target agreement by revealing
the transformation–preservation trade-off in Table 2. These
aggregate measures characterize the sampled benchmark;
operation-specific accuracy and pixel-level preservation re-
quire task-specific annotations.

B.4
Quality control
Every image is fully decoded, non-positive dimensions are
rejected, and the same aspect-preserving, multiple-of-16
geometry preprocessing used in training is executed as a
preflight check. Auxiliary loaders reject images with a side
shorter than eight pixels and reject truncated files by default.
A pass over 72,273 captioned records retains 67,271 and
removes 5,002 decoding or geometry failures. Segmenta-
tion masks covering less than 10% of an image are removed,
and a manually curated style bad-list removes 281 folders
or indices. The MegaStyle semantic audit evaluates 12,450
pairs and retains a pair only when both images receive YES;
7,552 pairs pass (60.7%). These checks are combined with
the source-specific automatic and semantic validation de-
scribed in the main paper.
B.5
Grouping and record formation
The common assembler groups source pairs by the opera-
tion key, subsamples and caps source-specific groups, and
selects a non-self peer as the demonstration. Source-specific
builders enforce the distinct-content/scene constraint stated
in the main paper; low-level records additionally forbid
references with the same internal _group_id. Assem-
bly uses random seed 42. Intermediate builders support
K ∈{1,2,3}, whereas the frozen TRANSFORM-360K man-
ifest is entirely K = 1. Thus 91,010 records yield 364,040
record-level image slots.

C.2
Optimization configuration
Table 8 lists the training configuration.
For each record, the training step draws one scheduler
index uniformly from the configured timestep interval (the
checked default spans the full interval), draws Gaussian
noise with scale 1, and forms the native Qwen flow-
matching target. The primary loss is MSE multiplied by the
scheduler’s training weight. Training uses cfg_scale=1.
No warmup or decay is introduced by the ConstantLR
scheduler.
Distributed sampling.
The K-bucket sampler groups
records by the number of demonstration pairs so all ranks
execute compatible tensor shapes. With K = 1, every rank
receives one record per optimizer step. Corrupt images are
not retried indefinitely: the checked loader attempts a path
once and then tries at most eight replacement records from
the same K bucket, logging failures as JSONL.
C.3
Resolution and image preprocessing
The frozen TRANSFORM-360K configuration uses an area
cap of 262,144 pixels and 512-pixel longest-side metadata.
The loader preserves aspect ratio, rounds dimensions down
to multiples of 16, and applies bilinear longest-side resize.
No random crop, flip, or color jitter appears in the checked
training path. The VLM wrapper independently resizes ref-
erences toward a 3842-pixel area, whereas the VAE refer-
ence branch uses its native 10242-pixel area target. DINOv3
receives a separate bicubic 224-by-224 input.

C.5
DINOv3 implementation details
This section records implementation details not repeated
with the derivation in the main paper. The frozen encoder is
DINOv3 ViT-7B/16. Inputs are resized to 224-by-224 and
normalized with mean (0.485,0.456,0.406) and standard
deviation (0.229,0.224,0.225). The implementation applies
the final model normalization, removes the CLS token and
the configured number of register tokens, and retains the
14 × 14 = 196 patch tokens. All encoder parameters are
frozen; only the predicted-image branch preserves its input
gradient.
For the DINO relation equations in the main paper,
change scores are detached, clamped non-negative, raised
to α = 1, and normalized over patches. The query map
in source_gt mode is computed from detached query-
source and target features; it localizes the edit but never
replaces the differentiable source-to-prediction direction.
No cross-scene patch correspondence is used.
The relation configuration uses dino_mode=pair_r
elation, λDINO = 0.003, σmax = 0.5, linear wσ, dino
_every=1, α = 1, source_gt query weights, 224-pixel
DINO input, and a gradient probe every 50 steps. Direct
perceptual, delta-consistency, and QwenVL relation losses
are disabled.

E.1
Baseline provenance and inference protocol
The corpus-controlled comparison uses the Relation252K-
trained CrossPair checkpoint. RelationAdapter (Gong et al.,
2025) uses its released Relation252K checkpoint. Following
the provenance statement in the main paper, the released
LoRWeB (Manor et al., 2026) comparison is categorized as
using Relation252K together with additional training data.
The Qwen-Image-Edit-2511 (Wu et al., 2025) row uses the
frozen base editor without CrossPair LoRA weights. The
TRANSFORM-360K checkpoint is added only to the OOD
panel.
The methods retain their public native generation inter-
faces, including method-specific canvas construction and
output extraction. “Same output resolution” in the main
comparison refers to the common evaluation image size: all
metric inputs use the same 512-pixel maximum long edge
after output extraction.

LPIPS.
LPIPS (Zhang et al., 2018) uses the AlexNet back-
bone. RGB images are mapped from [0,255] to [−1,1]. Gen-
erated images are resized to the target dimensions with
Lanczos interpolation before evaluation. The evaluation
command defaults to a 512-pixel maximum long edge for
both generated and target images; the reported launchers
explicitly set this value.
Aggregation.
The evaluator writes per-sample scores, per-
task means, and an overall micro mean in which every valid
query contributes one value. The main table uses this query-
level micro average, not a transformation-level macro aver-
age. No confidence interval or significance claim is made
for deterministic metrics.
E.3
Blinded GPT-5.5 ranking
We use gpt-5.5-xhigh through an OpenAI-compatible
Responses API. For each query, the request contains the
reference before, reference after, query source, and all can-
didate outputs. The target image and method names are
never supplied. Candidate order is shuffled once per query
using seed 20260724 + i × 1009, where i is the metadata
index. There is one request per query (repeats=1), with
four candidates in-domain and five candidates OOD.
Before transmission, every image is EXIF-transposed,
converted to RGB, downscaled with Lanczos to a maximum
side of 768 pixels, and JPEG-encoded at quality 90. Temper-
ature is omitted, the timeout is 240 seconds, and failed calls
are retried up to three times. In-domain uses two workers
and a 1,600-token response limit; OOD uses four workers
and a 2,000-token limit. Workers affect throughput only.
Returned JSON is accepted only if every ranking contains
every anonymized candidate exactly once without ties.
For each criterion we report Rank 1–K percentages and
mean rank. Percentages sum to 100% within a method.
Rank-1 confidence intervals use 1,000 query-level boot-
strap resamples and the 2.5/97.5 percentiles. We addition-
ally export Rank-1 frequency by display position to audit
residual position bias. The evaluation artifact retains the ran-
dom candidate mapping, raw request/response JSON, parsed
rankings, failure log, and resume manifest. The completed
common intersections contain 1,091 in-domain queries and
428 OOD queries, each judged once. The archived summary
files were finalized on July 26 and July 27, 2026, respec-
tively.
