ABSTRACT
Visual effects are often easier to demonstrate via reference than to describe in
words. We study effect-reference editing, where a reference image shows a de-
sired visual effect and language identifies which properties should guide the edit.
Existing single-pass editing techniques often fail to make fine-grained edits, re-
sulting in unintended changes to source content or deviations from the refer-
ence effect. We introduce KINESYS, a test-time adaptation framework for effect-
reference editing that combines reference-aware and source-aware feedback to
transfer the desired effect while preserving the composition and content of the
original shot. To ensure KINESYS can produce a diverse set of edits that pre-
serve the source, we develop a robust optimization strategy in which the generative
model is fine-tuned across multiple noise samples and optimization runs. Evalu-
ation with VLM judges, source preservation metrics (LPIPS, TPIPS), and a user
study shows that KINESYS outperforms state-of-the-art image editors in source
preservation; on effect transfer, it remains competitive with Nano Banana 2 and
outperforms open-weight editors.

INTRODUCTION
Recent open-weight and proprietary image editors can make convincing changes to existing im-
ages (Labs, 2025; Wu et al., 2025; Raisinghani, 2026; OpenAI, 2026; Team Seedream et al., 2025).
Editing visual effects nevertheless exposes a difficult control problem: artists often need to add el-
ements such as smoke, fire, or rain, or introduce visible damage, without unintended changes to
the source subjects, camera pose, framing, or scene object layout. An instruction-based edit such
as “add tire smoke behind the car” names the new element but does not specify its texture, color,
scale, density, placement, or interaction with the road and vehicle. A visual reference can supply
these details, but the editor must separate the properties that define the desired effect from incidental
reference content. The central challenge is therefore to realize the requested effect strongly enough
while preserving the source subject and scene structure.
We study effect-reference editing: the user provides a source image, an effect reference, and a text
instruction identifying which visual and spatial properties should guide the edit. The user specifies
which effect properties to transfer through reference-grounded yes-or-no questions and may include
a mask to localize the edit. The effect reference specifies what to introduce. We use source preserva-
tion to mean retaining the camera pose, framing, scene object layout, and subject appearance except
where the requested effect requires a change. Modern in-context editors can accept source images,
references, and language through a common interface (Labs, 2025; Team Seedream et al., 2025),
making them a natural basis for this setting.
A single editing pass may under-edit, producing a weak or generic result, or follow the reference
too closely and alter the subject, viewpoint, or scene layout, as illustrated in Figure 1. A natu-
ral response to single-pass failures is to evaluate candidate edits and use that feedback to improve
subsequent outputs. KINESYS fine-tunes the generator using reference-grounded visual question
answering (VQA): a vision-language model (VLM) answers the supplied questions about each can-
didate. These judges provide different information: our Gemma-based VQA judge (Gemma Team
et al., 2026) sees the reference but not the source and assesses the selected effect properties, while
EditReward (Wu et al., 2026b) sees the source but not the reference and assesses instruction fol-
lowing and visual quality. We combine these judges to support effect transfer that preserves the
source.
However, optimizing the generator with complementary feedback remains challenging. The same
editing request can produce different results depending on the random noise used to generate its
candidates (Ma et al., 2025; Guimaraes & Perona, 2026; Ben-Hamu et al., 2024; Kim et al., 2025).
Because these candidates also provide the feedback for fine-tuning, an unlucky initial set can steer
the generator toward a poor solution. To reduce this dependence, KINESYS starts K independent
fine-tuning runs, each using N fixed-noise candidates, then prunes runs and selects a checkpoint.
Together, these design choices adapt KINESYS to one request, allowing it to produce several ver-
sions of the referenced effect from unseen noise samples while preserving the source. As Figure 6
shows, new noise changes details such as texture, shape, density, and placement, giving artists sev-
eral interpretations of the same effect to compare.
We evaluate KINESYS on 81 editing requests spanning eight visual effects. KINESYS achieves the
strongest source preservation scores among the evaluated methods, remains competitive with Nano
Banana 2 on editing quality, and leads the evaluated open-weight editors on both source preservation
and editing quality. The blinded user study shows that participants selected KINESYS more often for
source preservation against Nano Banana 2 (Raisinghani, 2026) (45.3% versus 24.7%) and Step1X-
Edit (Liu et al., 2025a) (53.6% versus 20.9%), while effect-transfer preferences were competitive
with Nano Banana 2 and favored KINESYS over Step1X-Edit.
Our contributions are threefold:
• We introduce KINESYS, a test-time generator adaptation framework for reference-based vi-
sual effect editing in images that uses reference-grounded and source-aware VLM feedback
to perform effects editing that preserves the source without effect-specific training data.
• We develop a robust optimization strategy for fine-tuning the generator with LoRA using
N fixed-noise candidates per run and pruning across K independent runs, with an early
diversity penalty to discourage candidate collapse.

• We create a benchmark of 81 editing requests across eight effects with VLM and human
judges measuring editing quality for effect transfer and source preservation. Our method
outperforms the evaluated open-weight models and surpasses Nano Banana 2 in source
preservation while remaining competitive on effect transfer.

RELATED WORK
Dataset-trained and reference-guided image editing. Image editors learn shared behavior from
paired or synthetic data, as in InstructPix2Pix (Brooks et al., 2023). Paint by Example and Mim-
icBrush transfer reference content into source regions (Yang et al., 2022; Chen et al., 2024); FreeEdit
combines reference and language for mask-free editing (He et al., 2024); and Visual Instruction
Inversion infers an operation from a before-and-after pair (Nguyen et al., 2023). Recent image
editors and unified multimodal models condition image generation or editing on images and lan-
guage (Black Forest Labs et al., 2025; Labs, 2025; Wu et al., 2025; Zhang et al., 2025; Team See-
dream et al., 2025; Jiang et al., 2026; Diao et al., 2026). KINESYS adapts the generator to one
effect-reference request without an effect-specific training set or target edited image.
Generative visual effects. Recent visual-effects generation and compositing work includes Mag-
icVFX, VFX Creator, Omni-Effects, and Over++ (Guo et al., 2024; Liu et al., 2025b; Mao
et al., 2025b; Qi et al., 2025). EffectMaker learns reference-based VFX generation from a video
dataset, while P-Flow refines prompts against a reference at test time with a fixed video gener-
ator (Yang et al., 2026; Zhao & Shou, 2026). KINESYS instead adapts a generator for one im-
age edit using a source and effect reference, with the reference defining the effect and the source
defining what stays unchanged.
Request-specific and feedback-driven adaptation. Imagic and UniTune (Kawar et al., 2023;
Valevski et al., 2023) fine-tune a diffusion model for one source image and target text. DRaFT
directly optimizes diffusion parameters against a reward, while HIVE, InstructRL4Pix, CogniEdit,
and NP-Edit train shared editors with feedback or dataset supervision (Clark et al., 2024; Zhang
et al., 2024; Li et al., 2024; 2025; Kumari et al., 2026). SPIE uses AI feedback for concept-specific
adaptation from a small set of reference images (Benarous et al., 2025).
Most closely related, Dual-Process uses a VLM to guide request-specific fine-tuning of an image
generator (Luo et al., 2025). It asks whether generated images satisfy a control question, then uses
the answer likelihood to update LoRA weights on the generator. This provides a way to learn a visual
control without a task-specific training set. KINESYS extends this VLM-guided adaptation to effect-
reference editing, with the source image constraining subject appearance and scene composition.
Complementary feedback for reference-guided editing. HIVE, ADIEE, EditScore, and EditRe-
ward evaluate an edit against its source and instruction without an effect reference (Zhang et al.,
2024; Chen et al., 2025; Luo et al., 2026; Wu et al., 2026b). Reference-aware evaluators include
ICE-Bench, which judges the instruction, source, reference, and result, and EditCLIP, which com-
pares an edit with a paired reference transformation (Pan et al., 2025; Wang et al., 2025). EVR uses
multidimensional reference-aware feedback for dataset-level post-training of multi-reference edi-
tors (Miao et al., 2026). KINESYS combines both feedback roles within request-specific fine-tuning.
Reward-guided inference and test-time scaling. Inference-time scaling commonly holds the gen-
erator fixed. Best-of-N and adaptive pruning search over noise inputs or partial candidates (Ma
et al., 2025; Guimaraes & Perona, 2026; Qu et al., 2026; Yu et al., 2026); D-Flow, RewardFlow,
FMTT, trajectory control, and closed-loop generation optimize noise, sampling dynamics, or latent
controls (Ben-Hamu et al., 2024; Susladkar et al., 2026; Sabour et al., 2025; Chang et al., 2026;
Zhao et al., 2026); and iterative editors revise outputs over multiple rounds (Bai et al., 2025; Zeng
et al., 2026). KINESYS instead allocates compute across independent fine-tuning runs and returns
an editor that can produce several versions of the referenced effect while preserving the source.

Existing editors can produce convincing image edits, but on effect-reference requests they can miss
selected effect properties or alter the source subject and scene, as Figure 1 illustrates. We propose
KINESYS, a test-time adaptation strategy where VLM judges evaluate effect transfer and preserva-
tion of the source image structure and provide feedback to update the generative model.
At each fine-tuning step, KINESYS renders N candidate edits from different fixed noise samples.
Reference-grounded VQA and EditReward evaluate each candidate. KINESYS uses their feedback
to update only the LoRA weights ϕ (Hu et al., 2021). The base editor, text encoder, and feed-
back models remain fixed. Independent fine-tuning runs explore different noise sets before the final
adapted LoRA weights are selected. Figure 2 illustrates the KINESYS framework.
3.1
COMPLEMENTARY EDITING FEEDBACK
Following Dual-Process (Luo et al., 2025), a frozen vision-language model compares the effect
reference r with each candidate edit yi and answers targeted questions about properties such as the
appearance, placement, or interaction of the introduced element. For each of the Q questions qℓ, the
desired answer aℓis Yes. The VQA loss averages the negative log-likelihood of these answers, so
lower loss indicates clearer realization of the selected effect properties.
VQA compares each candidate edit with the effect reference but does not see the source, so it cannot
directly assess unwanted changes to the original subject or scene. We therefore also use EditRe-
ward (Wu et al., 2026b), a learned reward model that sees the source, instruction, and candidate
edit. It predicts two scores: instruction following Ri,follow and visual quality Ri,quality. The first
judges whether an edit is accurate, complete, and limited to the request; the second judges realism

3.2
ROBUST OPTIMIZATION
Learning from several candidate edits. A single noise sample can produce a weak edit or one with
unintended source changes, and fine-tuning only that candidate risks adapting the editor around a
poor starting point. KINESYS therefore learns from N candidate edits within each run. At the
start of the run, it draws N noise samples ϵi and reuses them throughout fine-tuning. At each step
t ∈{1, . . . , T}, the current editor renders one candidate from each sample. Reusing the noise makes
successive steps comparable and lets feedback track each candidate’s progress as the editor changes.
Reward-based candidate weighting. Within a run, all candidates shape the same LoRA. Equal
weights would give an edit with artifacts or unintended source changes as much influence as a
stronger edit. We smooth each EditReward score over optimization steps, standardize it across the
N candidates, and average the two scores per candidate. A softmax across these averages yields
weights αi that sum to one. This de-emphasizes poorly scored edits without discarding them;
weights are recomputed between updates, then detached and held fixed during each LoRA update.
Appendix C.2 gives the smoothing, normalization, and weighting equations.
Maintaining candidate diversity. An artist editing smoke around a car may want several valid
results: each should reflect the reference smoke and maintain the original scene composition, while
the smoke plume can vary in shape, density, and precise placement. The paired outputs in Figure 6
illustrate variations from noise samples. During fine-tuning, however, shared objectives can draw
all N fixed-noise candidates toward similar appearances. KINESYS includes a diversity term D to
discourage early convergence among the fixed-noise candidates.
Following repulsive particle objectives (Liu & Wang, 2019; Corso et al., 2023), D averages radial
basis function (RBF) similarities across distinct candidates. The complete optimization objective
combines the weighted candidate losses with this diversity penalty:

Independent fine-tuning runs. Candidate weighting reduces the influence of poor edits, but all
N candidates still shape one LoRA. Putting all samples into one run would keep their updates
coupled, so a promising starting set could still be pulled toward a compromise with less useful ones.
KINESYS instead starts K = 5 independent runs, each with its own LoRA parameters ϕk and its
own N fixed-noise samples. These K sets of N noise draws allow different starting sets to improve
independently; the runs exchange neither parameters nor candidates. The candidate and run study in
Section 4.3 supports this compute-limited configuration: three candidates score highest among the
tested widths, and multiple independent runs improve the lower-of-two score over one run.

Pruning and checkpoint selection. Not every starting set deserves the full tuning budget. KI-
NESYS therefore saves intermediate LoRA checkpoints and uses the first two scheduled checkpoint
boundaries to rank runs by recent VQA and EditReward feedback. Lower-ranked runs stop, leaving
three after the first pruning point and two after the second. The counts limit compute, but the search
remains open across multiple runs until a separate step selects one saved checkpoint.
To favor a checkpoint that works beyond the fixed noise samples used for fine-tuning, KINESYS
renders an evaluation image using the same held-out noise sample at every saved checkpoint. It
selects the LoRA parameters ϕ⋆whose evaluation image has the highest EditReward score. The
selected parameters give the artist an adapted editor that can produce further effect variations from
fresh noise while retaining the source scene. Appendices C, D, and A provide implementation
details, prompt templates, and additional visual results.

EXPERIMENTS
We test whether KINESYS transfers a reference effect while preserving source content and structure.
We compare it with open-weight and proprietary editors in Sec. 4.2 and report ablations in Sec. 4.3.
4.1
EXPERIMENTAL SETUP
Dataset and tasks.
Our evaluation contains 81 effect-reference editing requests across eight cat-
egories: boat wakes, vehicle dents, explosions, fire, puddles, cast shadows, smoke, and snow. The
requests use 78 distinct source photographs and 63 effect references. Each edit request includes a
short effect-editing prompt and three yes/no questions reused within its effect category. These ques-
tions test placement, realism, and a defining effect property against the reference image. Appendix B
provides more details on dataset construction.
Baselines.
We compare KINESYS with six direct open-weight editors: FLUX.2 Klein 4B (Labs,
2025), Qwen-Image-Edit (Wu et al., 2025), OmniGen2 (Wu et al., 2026a), Step1X-Edit v1.2 (Liu
et al., 2025a), ACE++ (Mao et al., 2025a), and ICEdit (Zhang et al., 2025), plus proprietary Nano
Banana 2 (Gemini 3.1 Flash Image) (Raisinghani, 2026). All direct editors receive the source and
instruction, and receive the effect reference where supported. They generate a result without per-
request tuning or verification questions. Mask-capable editors receive a full-image mask; all base-
lines can edit the entire image.
Native FLUX.2 Klein 4B receives the same source, effect reference, mask, and generation settings
as KINESYS, serving as its unadapted control. Our adapted Dual-Process baseline (Luo et al., 2025)
fine-tunes the same image-conditioned generator with the same instruction, source, reference, and
three questions as KINESYS, using only VQA feedback. For the automated comparison, KINESYS
uses a full-image mask because some baselines do not support spatial masks.
KINESYS configuration. For the main comparison and feedback ablation, a frozen Gemma 4 E4B-
it VLM (Gemma Team et al., 2026) answers the reference-grounded questions. Each run uses
N = 3 fixed-noise candidates for up to T = 100 steps, saving checkpoints at the labels listed in
Appendix C.4. KINESYS starts K = 5 independent fine-tuning runs and uses VQA and EditReward
feedback to retain three at the first pruning point and two at the second.

We compare each edit with its source using LPIPS distance (Zhang et al., 2018) and TPIPS under
its “overall” setting (Wang et al., 2026). LPIPS measures distance in learned visual features, while
TPIPS measures perceptual similarity conditioned on a text prompt. We use both as proxies for
overall source preservation; neither score directly measures camera pose, object layout, or subject
identity. Gemini and EditScore-72B judge broader editing quality that includes source consistency.
An unchanged edit can score well on similarity while failing to transfer the effect, so we interpret
these measures alongside the visual results and user study.
User study. Because automated judges are imperfect proxies for human judgment, we also ran a
blinded user study; the final analysis includes 16 edits, two per effect category. We compared KI-
NESYS with Step1X-Edit v1.2, the highest-scoring evaluated open-weight editor in Table 1, and with
proprietary Nano Banana 2. We report 41 completed response sets for Nano Banana 2 and 40 for
Step1X-Edit; most respondents are not VFX experts. Each response set contributes 16 paired com-
parisons, with separate source-preservation and effect-transfer judgments and ties allowed. Figure 3
reports preferences. Appendix E gives the survey protocol, preferences by effect family, and an
example survey question.

CONCLUSION
KINESYS adapts a generator to transfer a reference-demonstrated effect while preserving the source
shot’s composition and content. Complementary VLM feedback and independent fine-tuning runs
support this balance, while fresh-noise samples offer multiple edit variations. On the shared evalua-
tion cases, KINESYS achieves better LPIPS and TPIPS scores than Nano Banana 2 and is preferred
for source preservation in the blinded user study, while remaining competitive on editing quality and
effect transfer. It leads the evaluated open-weight editors on Gemini and EditScore-72B.
The approach still depends on what its generator can render and its VLM judges can recognize:
an unfamiliar creature with a rare stylized electrical effect, for example, may be difficult to edit
faithfully.
Bad starting noise can still yield a weak edit, and per-request fine-tuning adds la-
tency. KINESYS is a first step towards frameworks that enable effect transfer while preserving
source content and structure.

EVALUATION DATASET CONSTRUCTION
Requests and effect families. We evaluate 81 requests across eight effect families. Each pairs
a source photograph with a reference photograph showing the desired effect on different content;
there is no target edited image. These requests use 78 distinct source photographs because three
car photographs appear in both the dent and fire families. They use 63 distinct effect references;
13 of those references serve between two and four requests within their family. Figure B.1 shows
the request split, and Table B.1 gives the family counts and the properties selected for verification.
Family sizes range from eight to 13 requests; reported automated scores weight the retained results
from each request and seed equally.
Source and reference pairing. We selected each request’s effect reference by reviewing the source
photograph alongside references from the same effect family, without using a generated target edit.
A reference may serve multiple requests within its family.
Instructions and questions. We used one instruction template per effect family. It describes the re-
quested effect, treats the reference as an exemplar of selected effect properties, and avoids describing
the reference’s own scene. Editors and judges received the same instruction.
In the intended workflow, users define questions to select which properties of the reference effect
to transfer. For this benchmark, we authored three fixed yes/no questions per family. They check
where the effect appears, whether it looks realistic, and whether a defining property matches the
reference. For example, the questions about cast shadows ask whether the shadow falls beneath
the subject, is sharp and well-defined, and matches the reference’s direction and length. The VLM
receives the reference as Image 1 and the candidate edit as Image 2; the desired answer to each
question is “Yes.” The questions are reused across requests within a family and remain fixed during
fine-tuning. Section D gives the model-facing question format.
Image preparation and mask policy. Source and reference photographs were downscaled, without
upscaling, to a longest side of at most 768 pixels. The editor’s per-request image size was then
rounded down to a multiple of 16. The adapted editor used a reference-conditioning longest-side
cap of 384 pixels, while the in-loop VLM compared the candidate with the reference at its working
resolution of at most 768 pixels. The automated benchmark specifies a whole-image edit region;
mask-capable editors receive a full-image mask, including for effects that could be localized. The
hand-drawn masks in the Applications figure are examples outside these 81 requests.

Each surviving run may terminate before the nominal budget of 100 updates using a rule based on
reward drawdown. The monitored reward is the mean EditReward over the run’s N candidates,
smoothed by a mean over the trailing 10 steps. Stopping cannot occur before step 50 and requires
this smoothed value to remain more than 0.3 below its running peak for three consecutive steps. On
stopping, the run restores its best saved LoRA state from a chunk boundary.

C.4
IMPLEMENTATION DETAILS
Generator and optimization. The generator is FLUX.2 Klein 4B (Labs, 2025), using checkpoint
black-forest-labs/FLUX.2-klein-4B. It runs in bfloat16 with four flow steps and guid-
ance scale 1.0. Inpainting runs at the source resolution with the reference-conditioning longest side
capped at 384 pixels. The LoRA (Hu et al., 2021) has rank 16, is applied to transformer attention and
feed-forward projections, and uses AdamW (Loshchilov & Hutter, 2019) with learning rate 5×10−5.
Each fine-tuning run uses up to T = 100 optimization steps, with checkpoints at zero-indexed labels
15, 30, 45, 60, 75, 90, and 99, corresponding to 16, 31, 46, 61, 76, 91, and 100 updates. Only the
LoRA matrices are updated; the base generator and text encoder remain frozen. The Dual-Process
baseline uses the same image-conditioned generator and inputs but only VQA feedback; KINESYS
also uses EditReward feedback and the candidate and run search.
Feedback models and search schedule. The in-loop VLM is frozen Gemma 4 E4B-it (Gemma
Team et al., 2026), using checkpoint google/gemma-4-E4B-it. For each question, it receives
the effect reference as Image 1 and the candidate edit as Image 2, then answers “Yes” or “No.”
Differentiable EditReward uses the released Qwen2.5-VL-7B checkpoint with equal instruction-
following and quality weights, wfollow = wquality = 0.5 (Wu et al., 2026b). Each fine-tuning run
uses N = 3 fixed-noise candidate edits. The task objective uses λVQA = 1 and λER = 2, while the
diversity weight begins at 1 and decays to zero after 60% of the fine-tuning schedule. Search begins
with five fine-tuning runs and prunes 5→3 at checkpoint label 15 and 3→2 at label 30.

D
OPTIMIZATION AND EVALUATION PROMPTS
This section records the model-facing evaluation and optimization templates used in the canonical
experiments. Angle-bracketed fields are replaced at runtime. Line wrapping, markup, and punctua-
tion have been normalized for typesetting; the substantive wording, scoring criteria, and image order
are retained. The VQA and EditReward prompts affect fine-tuning gradients, and EditReward also
selects the final checkpoint; the Gemini prompts are evaluation-only and never enter fine-tuning,
allocation, or final checkpoint selection.
D.1
GENERATION INPUTS
Each editor receives the request’s source, effect reference where supported, and the same fixed
instruction; mask-capable editors also receive the full-image mask. The adapted FLUX.2 Klein 4B
generator receives both images as inputs.
D.2
REFERENCE-GROUNDED VQA
For every binary criterion, the frozen VLM receives the effect reference first and the current candi-
date second. The VQA objective averages the negative log-likelihood of the desired answers across
the three fixed questions for each request. The model-specific chat template wraps the following user
content. The assistant turn contains the target answer; cross-entropy uses only its answer tokens.
Image 1: <effect reference>
Image 2: <candidate edit>
<reference-grounded yes/no question> Answer with Yes or No.
Target answer: Yes
For example, one snow criterion is: “Does the snow in Image 2 cover the rooftops and lawns as it
does in Image 1?” Each request contains three such criteria, which remain fixed during optimization.

D.3
FROZEN GEMINI 2.5 FLASH SCORE JUDGE
The absolute Gemini 2.5 Flash evaluator (Comanici et al., 2025) receives images in the order source,
edited candidate, effect reference. Its system instruction is:
You are a meticulous, impartial image-editing evaluator. You are shown
an EDITED image produced from a SOURCE image by an edit instruction,
sometimes the SOURCE image itself, and sometimes a REFERENCE image
that exemplifies the desired effect or style. You rate three
dimensions on a 0-10 scale (0 = terrible, 10 = perfect). Be
calibrated and use the full range. Respond with ONLY a JSON object,
no prose, no markdown fences.
For the three-image reference-conditioned case, the user message is:
Edit instruction: ’<instruction>’
There are 3 image(s): the FIRST image is the SOURCE; the SECOND image is
the EDITED image; the THIRD image is the REFERENCE.
Judge source_consistency by how faithfully regions NOT targeted by the
instruction are preserved from the SOURCE.
A REFERENCE image is provided: it is an EXEMPLAR of the desired
effect/style on a DIFFERENT subject (NOT a pixel-exact target).
Judge edit_adherence by how well the EDITED image achieves the SAME
effect/style shown in the REFERENCE while following the instruction
- do NOT penalize differences in subject, scene, or exact pixels
between the edited image and the reference.
Rate three dimensions, each an integer or decimal from 0 to 10:
- perceptual_quality: photorealism and absence of
artifacts/blur/distortion in the edited image.
- source_consistency: how faithfully regions NOT targeted by the
instruction are preserved.
- edit_adherence: how well the intended edit was actually implemented
(per the note above).
Return JSON exactly: {"perceptual_quality": <number>,
"source_consistency": <number>, "edit_adherence": <number>}
The Gemini score in Table 1 is the mean of perceptual quality and source consistency. The prompt
also returns an edit-adherence score, which is not included in this aggregate.

Each blinded survey item used a 2 × 2 comparison video. The source and effect reference remained
