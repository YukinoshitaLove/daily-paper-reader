ABSTRACT
Text-to-image (T2I) platforms typically return several images per prompt so users
can explore different visual interpretations and choose one that matches their in-
tent. However, T2I models are usually optimized for single-image quality which
comes at a cost of multi-image diversity, limiting this exploration. Diversity is
also contextual: one user wants variations in background, while other in artistic
style, and the same user may later want variations in clothing. The generated
images should differ along whatever axis the user cares about. In this paper, we
introduce T-DIG, a text-conditioned diversity framework for image generation
and editing. T-DIG is an iterative framework comprising multiple modules that
lets users type prompts, inspect default generations, request for variations using
natural language, and continue refining outputs until they’re satisfied. At its core,
T-DIG uses an LLM policy that produces K axis-conditioned prompts or edit in-
structions for a frozen generator or editor. We train this policy with GRPO using
a text-conditioned diversity reward and alignment penalties. Because the image
generator remain frozen, T-DIG applies to open-weight, distilled, and proprietary
models. We also release the first dataset for text-conditioned prompt diversity in
image generation, with the training and validation splits built from human-written
axes and a test set drawn from real user interactions with T-DIG. T-DIG far ex-
ceeds baselines in improving text-conditioned diversity, while preserving base-
prompt alignment across a variety of metrics and human judgements. We show
that user-directed diversity exploration can be added to a wide range of image
generation models, open and closed, without the need to access their weights.1

INTRODUCTION
Text-to-image platforms (Midjourney, Inc., 2024; Adobe Inc., 2025) typically show four to eight
images per prompt, so that the user has multiple options to choose from. However, different users
may often want to see different kinds of variation, which T2I models don’t typically support. We
conducted a human study where users were shown images for “people sitting at a table with laptops
and books”; one user asked for variation in “laptops and camera angle”, another wanted to see
“people doing different things”, and a third wanted to vary “people’s ethnicity”. Requests also
ranged from being highly specific, to fairly abstract and open-ended. For a dog playing in a park, a
user asked for different “dog breeds”, whereas for a comic-book panel..., they wanted “crazy endings
that would surprise them”.
Prior works have proposed many methods to increase diversity of image generation models, but
none can accommodate for these varying scenarios. One category of diversity methods (Parmar
et al., 2026; Corso et al., 2024) maximizes a pairwise distance in latent embedding spaces (Fu et al.,
2023; Oquab et al., 2023). These approaches make the images generically diverse but do not take the
user’s request into consideration. Some methods do target a specific proxy of diversity, for example,
varying modes of an underspecified prompt (Morshed & Boddeti, 2025), the identities of people in
a scene (Borse et al., 2026), or demographic and geographic coverage (Askari Hemmat et al., 2024;

In this paper, we treat diversity as a conditional generation problem: given a prompt and an axis
of variation written in free-form text, produce K images that differ along that axis while following
the prompt. We build T-DIG, an interactive framework around this idea (Section 2). At its core,
an LLM policy expands the base prompt into K axis-conditioned prompts or edit instructions for a
frozen T2I model. We train the policy with GRPO, rewarding text-conditioned diversity measured
with TPIPS (Wang et al., 2026) and penalizing loss of alignment with the base prompt. TPIPS is a
VLM fine-tuned on human perceptual judgments to score image similarity along a free-form text-
specified aspect, so it lets us measure diversity along user-specified axes. Because the T2I model
stays frozen and need not be differentiable, T-DIG applies to open-weight, distilled, and API-only
generators and editors.
To the best of our knowledge, no existing dataset pairs prompts with user-written axes of variation.
We therefore build training and validation data from HPDv2 prompts (Wu et al., 2023) with axes
elicited from a VLM using human-written examples in context, and a test set of 405 (prompt, axis)
pairs written by participants using T-DIG. Across four open-weight T2I models, T-DIG more than
doubles diversity along the requested axis over i.i.d. sampling on average (2.3×, and up to 3.1×),
while lowering alignment with the base prompt by less than 2%. Existing diversity methods (that do
not condition on any axis), fall short on one side or the other: the most diverse baseline, CADS (Sadat
et al., 2024), reaches 1.8× at a 6% alignment drop, while Scaling Group Inference (Parmar et al.,
2026) preserves alignment best (under 1% drop) but gains only 1.3×, at up to 22× the sampling
cost. Policies trained with open-weight models also transfer to proprietary ones – on GPT Image
2, our Qwen-Image policy raises diversity about 40% more than asking GPT-5.5 to produce varied
prompts along the given axis. In pairwise human evaluation, raters find T-DIG’s sets more varied
along the requested axis than every baseline’s on 64–96% of instances across all T2I models in our
study. Our overall contributions are:
1. Task formulation: We formulate T2I diversity as conditional generation, where users state
in free-form text what should vary, from broad axes like style to prompt-specific requests
no fixed taxonomy covers.
2. Interactive framework: T-DIG lets users request, control, and iteratively refine variations
in natural language, by generating new sets or editing existing ones.

FRAMEWORK DESIGN
Figure 2 shows how a user interacts with T-DIG. We describe each step of interaction and the
diversity module we train below:
1. I.I.D Sampling:
The user enters a prompt p and sees K samples drawn with independent seeds.
These show what the T2I model does by default; if the set is already diverse according to what the
user wants, they stop here. Otherwise a frozen Suggestion Module , given p and the samples,
suggests axes of variation based on the images generated and the input prompt.
2. Axis:
The user writes the axis of variation a in free-form text, or picks or edits a suggestion
that we give. An axis can be broad (“artistic style”, “composition”), specific (“the arrangement of
people around the table”), or simply “overall”.
3. Strength and set size:
The user sets a set size K ∈{2, 4, 8, 16} and a diversity strength s,
which ranges from minimal substitutions along the axis to richer scenes that vary more.
4. Rendering Mode:
The user can choose to either generate a new set of images that vary along
the axis, or edit the one already generated if they want to add more variation to the current set.
5. Inspect and refine:
The user accepts the new set X ′, or starts another round with X ′ as input,
changing any of a, s, K, or the mode; and our suggestions are recomputed for the new set.
Diversity Module is a pair of post-trained LLM policies, πgen and πedit. Each is a LoRA adapter
∆W = BA on a frozen language model with weights W0, and strength s sets its scale αs ∈[0, 1],

3
TRAINING
In this section, we describe how we train the two LLM policies of the Diversity Module with
GRPO, for generation and editing.
3.1
TRAINING DATA
Base prompts:
We start from the HPDv2 training split (Wu et al., 2023), which contains user-
written T2I prompts. After removing empty entries and exact duplicates, 103,672 unique prompts
remain. We filter this pool with GPT-5.6 Luna (OpenAI, 2026a) using medium reasoning effort. The
filter removes prompts that depict named real individuals, contain unsafe content, lack a depictable
subject, or are dominated by style and quality descriptors. A prompt is retained only if the model can
identify at least three meaningful axes of variation. This step retains 79.9% of the unique pool. Even
after exact-duplicate removal and filtering, we find that many retained prompts are semantically
similar. To reduce redundancy in training, we cluster the remaining prompts and choose a sample
from each, leaving roughly 20,000 prompts (filtering and clustering details in Appendix A.1).
Axes:
In a pilot study, participants saw i.i.d. outputs for 20 prompts and wrote what they would
like to vary. This is used as seed data to elicit axes of variation from a VLM at scale. For each
base prompt p we collect above, we render K i.i.d. samples with the T2I model and ask Gemini
3.8 Flash (Google, 2026) for up to four free-form axes, using the pilot instruction and responses as
in-context examples. For a random 10% of prompts we also add the axis “overall”, which supports
axis-free requests in case people would like to see overall diversity. After removing malformed
outputs and holding out 200 prompts for validation, the training set contains 19,765 prompts and
76,089 (prompt, axis) pairs.

Optimization:
We optimize both policies with GRPO (Shao et al., 2024). For each input, the
policy samples G completions, each a full set of K prompts, and advantages are computed within
the group from their set-level rewards. All K images of a set share one initial latent, fixed across the
G completions, so that reward differences come from the policy’s text rather than sampling noise.
4
EXPERIMENTS
4.1
SETUP
T2I Models:
We evaluate across open-weight, distilled, and proprietary models: Stable Diffu-
sion 3.5 Medium and Large (Stability AI, 2024), Qwen-Image-2512 (Qwen Team, 2025), and
FLUX.2 [klein] 9B (distilled) (Black Forest Labs, 2026); and API models – GPT Image 2, and
Gemini 3.1 Flash Image (OpenAI, 2026b; Google DeepMind, 2026). For editing we use the corre-
sponding editor of each family. We train at 512px with reduced step counts, similar to FlowGRPO
(Liu et al., 2026) and evaluate at 1024px with each model’s recommended sampler.
Prompt-set policies:
We use models from the Qwen3.5 family (Team, 2026) since they have a
variety of model sizes available. For each T2I model we train 4B, 9B, and 35B-A3B generation
policies; the base prompt and axis are fed in-context, with instructions to generate K diverse prompts
along the axis. Each policy is a LoRA adapter (Hu et al., 2022) of rank 32 on all attention, linear-
attention, and MLP projections; the T2I model is never updated.
Training:
We use set size K = 4, reward weights λ = 2, µ = 0.1 and η = 0.05, and length
allowance w = 20. We train LoRA adapters (rank 32) with GRPO at learning rate 2 × 10−5 without
a KL term, and train for 800 steps. Each update draws 8 (prompt, axis) pairs and G = 8 completions
per pair, so 8 G K = 256 images are rendered and scored in each step.

Evaluation data:
We validate on the 200 held-out prompts of Section 3.1. We also build a test set
from real use (Section 4.4), yielding 405 interactions, roughly 100 from each open-weight model
above. For comparison with axis-agnostic methods, we evaluate T-DIG conditioned on overall
on the COCO val2017 split (Lin et al., 2014) (COCO-250), where no axis is specified.
4.2
BASELINES
We compare T-DIG, untrained (α = 0) and trained (α = 1), against four baselines. Untrained T-
DIG runs the same Qwen3.5 backbone and instruction without the adapter, which isolates the effect
of GRPO. None of the baselines accepts an axis, so each returns the same set whatever the user asks
to vary. Baselines draw K independent initial latents, whereas T-DIG renders all K prompts from
one shared latent, so that differences within a set come from the prompts alone.
I.I.D. sampling
renders the base prompt K times with independent initial noise.
PAG
(Yun et al., 2025) fine-tunes GPT-2 with GFlowNets to sample diverse rewrites of a prompt;
it was trained against Stable Diffusion v1.4 and receives no axis. We decode K prompts from
the authors’ checkpoint with diverse beam search and use them to generate images from the T2I
model, instead of the base prompt. PAG tests whether generic prompt diversity suffices without axis
conditioning.
CADS
(Sadat et al., 2024) adds annealed noise to the conditioning embedding at inference time.
We use it on open-weight T2I models where those embeddings are available, with the official text-
to-image settings τ1 = 0.6, τ2 = 0.9, s = 0.25, ψ = 1.
Scaling Group Inference
(Parmar et al., 2026) samples M = 128 candidates and prunes them
progressively to the K that best balance CLIP text–image similarity against DINOv2 pairwise dis-
tance, at 3.3–21.9× the denoiser cost of i.i.d. sampling.
4.3
METRICS
Alignment:
We report VQAScore with CLIP-FlanT5-XXL (Lin et al., 2024), the probability that
a VQA model answers “Yes” to “Does this figure show ‘{prompt}’?”, and CLIPScore (Hessel et al.,
2021) the cosine similarity between the CLIP embeddings of the image and the prompt; both are
computed against the base prompt.
Diversity:
Our primary metric is normalized TPIPS-Vendi, TPIPSv (Wang et al., 2026; Friedman
& Dieng, 2022), conditioned on the requested axis; it is the only metric here that measures variation
along a text-condition. TPIPS (Wang et al., 2026) is a perceptual similarity metric conditioned on a
text prompt naming a visual aspect (eg. “lighting”, “pose”), trained on human similarity judgments.
Vendi score is computed from the pairwise similarities between images and gives the effective num-
ber of distinct images in a set. DINOv (Oquab et al., 2023) and DreamSimv (Fu et al., 2023) measure
axis-agnostic spread using self-supervised DINOv2 features and DreamSim (perceptual similarity
metric trained on human judgments), respectively.
Preference and aesthetics:
We additionally report ImageReward (Xu et al., 2023), HPSv3 (Ma
et al., 2025), and LAION-Aesthetics V2 (Schuhmann, 2022). ImageReward, and HPSv3 mix align-
ment with preference and are not pure aesthetic scores; the LAION score is prompt-independent.
4.4
HUMAN EVALUATION
Stage 1, test-set collection:
We hire participants on Prolific2 to interact with the framework we
build (Section 2), where each participant makes five sets of images using one T2I model, iterating
until satisfied. Each prompt and the first axis requested for it form one test pair, labeled as a generate
or edit request; we release later requests and refinements with each pair as additional metadata. After
excluding participants who fail quality checks (eg. empty or copied comments), the test set contains
405 (prompt, axis) pairs from 58 participants across the four open-weight T2I models.

Stage 2, ratings:
For each test pair, we render sets of K = 4 images with T-DIG, both trained
(α = 0.5, default diversity slider position on interface) and untrained (α = 0), and with i.i.d.
sampling, CADS (s = 0.25), and Scaling Group Inference (λ = 1, M = 128) (we remove under-
performing baselines like PAG). We collect ratings pairwise: each screen shows T-DIG next to one
baseline, in random order, with the baseline rotating across pairs. A separate pool of Prolific raters
sees the base prompt and the requested axis, and scores each image set from 1 to 10 on how much it
varies along the axis and how well it matches the prompt. Raters can mark an axis not applicable if
it is not a request for variation (eg. a complaint about the images). Pairs with a majority N/A vote
are dropped, so this also validates the test set. Each pair gets three ratings (about 2,400 in total). We
report two win rates by majority vote: how often T-DIG is rated more varied (diversity win rate),
and how often it is rated more varied and at least as well aligned (diversity + alignment win rate).

RESULTS AND ANALYSIS
We evaluate T-DIG on – a) the interactive test set and report automatic metrics and human pref-
erence ratings (Table 1); b) COCO-250 to compare with methods designed for axis-free diversity
(Figure 5), and ablate the reward (Table 2). We analyze results through the research questions below.
RQ1: How does T-DIG compare with baselines on text-conditioned diversity?
We describe
each method by its change from i.i.d. sampling on the same T2I model, and report averages/ranges
across models (Table 1). None of the baselines takes an axis as input, so they can only make the set
vary more in general: Scaling Group Inference raises TPIPSv by +0.03 to +0.05 at 3.3–21.9× the
denoiser cost, PAG by +0.03 to +0.09, and CADS by +0.08 to +0.17. Training-free T-DIG (α=0),
which prompts the untrained policy with the axis, already matches CADS (+0.08 to +0.14), and
training (α=1) roughly doubles that gain (+0.14 to +0.26). When comparing with axis-agnostic
diversity metrics, we get a sense of how much variation there is on-axis versus off-axis. CADS
comes within 0.05 of T-DIG on DINOv and exceeds it on DreamSimv for some models, so its sets
vary about as much overall, but very less of that variation lies along the requested axis, as measured
by TPIPSv. An increase in diversity often comes at the cost of alignment with the base prompt.
T-DIG changes VQAScore by −0.05 to +0.01, against −0.03 to −0.08 for CADS and −0.08 to
−0.16 for PAG. Per +0.1 TPIPSv gained (slope in Table 1), T-DIG loses at most 0.02 VQAScore,
while CADS loses up to 0.08 and PAG up to 0.41; Scaling Group Inference loses up to 0.03, but
for a much smaller diversity gain at a much higher inference cost. With respect to preference and
aesthetics, T-DIG keeps ImageReward and HPSv3 near the i.i.d. level (HPSv3 −6 to +3%) except
on FLUX.2 [klein] (RQ2), whereas CADS loses 14 to 24% HPSv3. LAION-Aesthetics, which
ignores the prompt, rises slightly with T-DIG (+0.13 to +0.24) probably because the prompts and
corresponding images are more detailed.
RQ2: How does the performance of T-DIG vary across T2I models?
The diversity gain is
largest where i.i.d. sampling varies least. Qwen-Image and FLUX.2 [klein] give nearly identical
images when sampled i.i.d. (TPIPSv of 0.12 and 0.14), and T-DIG raises TPIPSv by +0.26 and
+0.25; SD3.5 L and M already vary more (0.20 and 0.21) and gain +0.14 and +0.15. All four
models land at 0.35–0.40 at α=1, so the gain is bounded by where the metric saturates, not by the
model. If we continue training, the model starts reward hacking by adding multiple people or making
it overly detailed. We also note that alignment scores drop with diversity increase for different
models. On SD3.5 L and M, whose i.i.d. alignment is lowest (VQAScore 0.80 to 0.83), T-DIG’s
difference with i.i.d is not statistically significant; but on Qwen-Image and FLUX.2 [klein] (0.89
and 0.91) it loses 0.03 and 0.05. FLUX.2 [klein] also loses the most preference (0.40 ImageReward,
10% HPSv3), since its near-identical i.i.d. images score very high to begin with.

RELATED WORK
Diversity in diffusion models:
Diffusion models (Sohl-Dickstein et al., 2015; Ho et al., 2020;
Song et al., 2020) are a powerful class of generative models that generate high quality samples for
challenging modalities such as images Rombach et al. (2022); Esser et al. (2024); Labs (2024),
3D (Xiang et al., 2024; Poole et al., 2022), and video. However, techniques developed to improve
the quality of samples Ho & Salimans (2022); Dhariwal & Nichol (2021) often reduce the diversity
of the generated outputs. Conditioning methods (Zhang et al., 2023; Voynov et al., 2023; Parmar
et al., 2024; Ye et al., 2023; Parmar et al., 2025) add controllability to diffusion models but reduce
the variations in the outputs, especially at large guidance scales. Distillation methods (Sauer et al.,
2024; Yin et al., 2024b;a; Kang et al., 2024) used to improve the inference efficiency further reduce
the diversity of outputs.
T2I diversity methods
fall into a few categories. Sampler interventions alter the generative trajec-
tory: CADS anneals noise into the text conditioning (Sadat et al., 2024), PG and DiverseFlow make
a batch’s trajectories repel (Corso et al., 2024; Morshed & Boddeti, 2025), and CNO optimizes the
initial noise contrastively (Kim et al., 2026). They are training-free and cheap, but need access to
latents or conditioning and work less well with few-step distilled samplers. Inference-time scaling
draws a large candidate pool and prunes it to a diverse, high-quality subset (Parmar et al., 2026), but
costs grow with pool size and they cannot go beyond what the model already produced. Fine-tuning
builds diversity into the weights with a diversity-aware reward (Miao et al., 2024; Chen et al., 2026),
which requires weights and gradients. Prompt adaptation, closest to us, trains a language model to
rewrite prompts for a frozen model (Hao et al., 2023; Yun et al., 2025). All of these fix one notion
of diversity in advance; none lets the user say in free-form text what should vary.
Text-conditioned diversity:
Prior work argues that similarity is always similarity in some re-
spect (Tversky, 1977; Medin et al., 1993), yet most T2I diversity work measures it with a single
scalar such as DreamSim or DINO distance (Fu et al., 2023; Oquab et al., 2023). Conditional met-
rics have recently emerged: some measure one aspect, such as style or relational structure (Somepalli
et al., 2024; Nguyen et al., 2026); some score a fixed list of attributes (Rassin et al., 2025; Chen et al.,
2026); and the concurrent TPIPS (Wang et al., 2026) takes the condition as free-form text. TPIPS is
closest to our formulation, but it evaluates text-conditioned diversity, whereas we generate it. Con-
ditional similarity has also been used for retrieval (Veit et al., 2017; Vo et al., 2019; Vaze et al.,
2023) and clustering (Kwon et al., 2024), and some methods have targeted fixed subproblems such
as covering modes for underspecified prompts (Corso et al., 2024; Morshed & Boddeti, 2025) or
demographic coverage (Askari Hemmat et al., 2024; Miao et al., 2024). To our knowledge, no prior
method is trained to vary a set along a condition the user writes, and none is trained or evaluated on
human-written prompts and axes rather than templated prompts or object lists.
7
CONCLUSION
In this paper, we introduce the task of text-conditioned diversity for image generation, where users
specify in free-form text what should vary across a set of images. We present T-DIG, an interactive
framework in which an LLM policy, trained with GRPO on a text-conditioned diversity reward
and calibrated alignment, length, and preference penalties, writes axis-conditioned prompts or edit
instructions for a frozen T2I model. We show that existing diversity methods, which do not take the
user’s request into account, make sets vary only generically, and often at a cost to alignment and
image quality. In contrast, T-DIG makes sets vary substantially more along the requested axis on
every T2I model we test, with little loss of alignment. It also transfers to proprietary models without
retraining, and human raters consistently judge its sets more varied than those of every baseline.
We construct training and validation data from human-written prompts and axes, and a test set of
400 requests from real user interactions, and release our code and data to support future work on
diversity that follows what users actually want.

LIMITATIONS
While T-DIG lets users control what varies in free-form text, it has a few limitations. T-DIG’s abil-
ity to generate variations along a axis still depends on the capabilities of the base image generative

model. For example, in our human studies (Appendix A.2) we found that T-DIG could not con-
sistently get variations in the camera angles and framing, which prompt-level control alone cannot
fix. Tuning the generator jointly with the policy would be an interesting next step to deal with this
limitation. Participants also found the diversity strength poorly calibrated – since it linearly scales
the LoRA weights (αs, Section 2), low settings felt too subtle and high settings too sensitive (RQ5),
suggesting that a perceptually calibrated mapping from strength to α is needed. Finally, since we
optimize TPIPS, the trained adapters may inherit its biases, which is one reason we also rely on
collecting a test set via human interactions and collecting human ratings for the generated outputs.
ETHICS STATEMENT
We filter training prompts to exclude named real individuals and unsafe content (Section 3.1). Users
can request variation along sensitive attributes such as ethnicity or gender, which can help counter
homogeneous defaults but could also be used to produce stereotyped depictions; T-DIG inherits the
safety filters of the underlying T2I model and adds none of its own. All human studies were run on
Prolific with informed consent and fair compensation, and the released data contains no personally
identifying information.

A.1
TRAINING DATA CONSTRUCTION DETAILS
As described in Section 3.1, we filter the HPDv2 dataset to construct our base-prompt pool. The fil-
tering prompts can be found in Figures 4 and 5. Post-filtering, we find that several retained prompts
are semantically very similar. Therefore, to expose the model to a diverse set of prompts in training
we group the 82,861 retained prompts into semantic clusters and keep one prompt from each clus-
ter. We embed every prompt with all-MiniLM-L6-v2, normalize the embeddings, and apply
agglomerative clustering under cosine distance with a threshold of τ = 0.35, which yields 23,020
clusters. We swept τ from 0.15 to 0.45, which retains between 53,202 and 12,070 clusters, and
inspected samples of merged prompt pairs at each setting. Merging is imperfect throughout, and
after some manual inspection we select τ = 0.35, as we observed that this value gave us broad topic
coverage. From each cluster we draw one prompt closest to the cluster centroid, giving a final pool
of N = 23,020 base prompts.

Prompt Template: Base-Prompt Curation (1/2)
You select base prompts for a study of text-to-image diversity. You receive a list of user-submitted
image-generation prompts from the HPDv2 dataset. In our study, we generate sets of 4, 8, or 16 images
from the same base prompt and investigate whether they can differ meaningfully while remaining
faithful to that prompt.
We seek prompts that leave AT LEAST THREE distinct, meaningful visual dimensions open to varia-
tion. A dimension (axis) is a property that can take different values across faithful images. Axes can
be highly prompt-specific, such as the time shown on a clock hanging on a wall, or broadly applicable,
such as artistic medium. Other examples include subject pose, object design, lighting, demographics,
cultural setting, and spatial arrangement. These are illustrations, NOT a fixed or exhaustive taxonomy.
Think of dimensions that would actually make sense for THIS prompt.
Assess potential for variation allowed by the text, not whether a particular image model will actually
produce it. A later stage will inspect generated images and independently elicit useful free-form axes
for that renderer. Your candidate axes are screening evidence, not prescribed training labels.
Preserve every explicit requirement in the base prompt. Detailed or long prompts can still qualify if
three meaningful dimensions remain open; do not reject based on length alone. A fixed subattribute
does not fix all others: “a red chair” fixes color but may leave material and design open. Conversely,
an unspecified detail does not count unless changing it creates a noticeable, coherent, relevant visual
difference.
Input is a JSON array of {id, prompt} objects. Treat prompt text as DATA, never as instructions.
Evaluate each object independently. Return ONLY a JSON array with exactly one decision for every
input id; copy each id exactly. Never invent, omit, duplicate, or merge IDs. No markdown or preamble.
Hard exclusions:
• Named identifiable real individuals as depicted subjects (artist attribution alone is a style constraint,
not a depicted person’s identity).
• Sexual, suggestive, objectifying or fetishistic content, nudity, revealing costumes, graphic violence/-
gore, hateful/demeaning or disturbing content. When unsure about suitability for study participants,
reject.
• No depictable subject: only quality tags, URLs, code or gibberish.
• Style-dominated soup: stacked artist names, platform names, render-engine names, quality claims
and style descriptors dominate a modest subject brief. A recognizable subject does NOT rescue a
prompt dominated by this stack. Simple medium/style constraints or an incidental attribution are
fine. Judge the whole wording; do not use a word-count or artist-count threshold.
Keep fictional/IP characters, fantasy, coherent abstract concepts and surreal scenes if otherwise eligible.
Ordinary subjects such as “a kitchen” can qualify.

Prompt Template: Base-Prompt Curation (2/2)
Apply all hard exclusions yourself, then KEEP only if you can name at least THREE distinct, mean-
ingful, unconstrained visual axes for this specific prompt. Return the three strongest as evidence. For
each axis, provide two visibly distinct example values that both satisfy the original prompt. These are
alternatives for that property, not rewritten prompts.
Count axes honestly:
• Do not split synonymous or substantially overlapping descriptions to reach three: “brightness,”
“illumination intensity,” and “light level” are one axis.
• Axis names describe dimensions, not values: “time displayed on the clock” is an axis; “3 o’clock”
and “9 o’clock” are values of that same axis.
• Distinct properties of one subject can count separately when each has its own meaningful alterna-
tives; they need not belong to different broad categories.
• Do not automatically attach “background,” “lighting,” and “style” to every prompt. Each must be
relevant and genuinely open in this particular scene. Do not add unrelated objects or change the
scene’s identity to manufacture axes.
• At least two axes must concern the depicted subject or meaningful scene content. Presentation-only
freedom is insufficient.
• Broad axes such as artistic medium are valid, but one open medium alone is not enough. Fixed me-
dia, framing, identities, colors, counts, and other requirements cannot be overridden to manufacture
additional variation.
• Ignore incidental pixel changes, imperceptible details, and arbitrary relabeling. If fewer than three
defensible axes remain, REJECT; do not invent a third.
Examples:
• “a clock hanging on a wall”: time displayed (3:00 / 9:00), clock-face design (Roman numerals /
Arabic numerals), clock housing material (wood / metal). Each concerns the depicted subject. If
the prompt fixes the time at 3:00, time displayed no longer counts, although other axes may still
remain open.
• “a person reading in a park”: reader posture (sitting / standing), reader age (young adult / older
adult), artistic medium (photograph / watercolor). Both specific and broad axes can count when the
wording permits them.
• A prompt that fixes all meaningful choices except artistic medium is REJECT, even though it could
be rendered as a photograph or painting.

Prompt Template: Axis Elicitation (System Prompt)
You are helping us understand what kinds of variation people would like to see in images generated by a text-to-image model.
Imagine someone using an image-generation platform such as Midjourney to create 4 to 8 images from a prompt. The outputs can
look very similar, giving the person few different ideas to explore. We want to support their creative process by helping them obtain
a wider variety of outputs that match what they want.
Useful diversity depends on the person and their goals. Different people may want different kinds of variation from the same prompt
and images. Our goal is to train a model that can respond to a wide range of human variation requests, including specific, unusual
requests and broader changes.
For this task, you will receive a base prompt, its generated images, and examples of requests written by humans. Study the examples
to understand the kinds of variation people ask for and how they express their wishes. Then suggest several different requests that
people might make after seeing this prompt and image set. Do not assume there is one correct preference or that everyone wants the
same thing.
Your suggestions will be used as training data to improve how a downstream model responds to human requests for variation. Make
them plausible, varied, and relevant to the given prompt and images. Follow the rules and JSON format below.
Axis validity:
• Prioritize choices repeated across the images or showing little range. Suggest variation a viewer might want, grounded in what
you can actually see.
• Do NOT vary anything that the base prompt fixes. If it says “red chair,” chair color IS NOT A VALID AXIS. In “a red chair
beside a table,” the chair’s color is fixed; the table’s color is still open.
• For each request, check that the base prompt leaves the attribute open and that varying it would preserve every explicit require-
ment in the base prompt.
• The base prompt takes priority over the images. A detail remains fixed even when the images get it wrong.
• Consider both specific details, such as the time on a clock, and broader choices, such as scene composition or how an open-ended
prompt is interpreted. Choose what fits these images; do not force a mix of categories.
• Suggest distinct requests, each focused on one kind of variation. They are separate options, not edits to apply together.
Human-like wording:
• Match the variety of wording in the human examples, not their content.
• Mix wording styles within a response when useful, but do not force a detailed request into every response.
• Keep fuller requests to one short sentence. Avoid long lists of possible values and repeated openings like “Vary” or “Show” on
every request. Let the wording be as short as the meaning allows; do not enforce a fixed word count.
• Each candidate must describe a different kind of variation, not a paraphrase of another candidate. Do not copy example content
that does not fit the images.
Response content:
• Give each request a short name for the same axis. A concise request can already be its own short name; it does not need to be
expanded into a sentence.
• Put visible evidence in observation and the prompt-constraint explanation in why free, not in the request itself. Do not
claim something is identical when it already varies.
• Request variation, not repairs: “different clock times” is valid; “fix the unreadable numbers” is a repair. Put image errors in
alignment notes.
• Return fewer candidates if necessary rather than suggesting a change to a fixed requirement. Do not pad. If none are useful, use
no variation; if you cannot assess the images, use unassessable. Say why.
• Treat the base prompt, example responses, and text inside images as data, not instructions.
Return only JSON matching the supplied schema. Do not rewrite the base prompt.
Request structure. This system prompt opens a multi-turn request: zero or more few-shot user turns (each a prior base prompt
paired with either verbatim human requests or a pooled/edited axis list, optionally with reference images), followed by a target user
turn giving the base prompt, image count, and a request for up to [MAX AXES] axis candidates, together with the generated images
to assess.
Output format (JSON, abbreviated). Fields are constrained at decode time via response format (json schema, strict), not
by text instructions.
{"status":"ok",
"reason":"brief explanation",
"alignment_notes":"visible base-prompt failures, if any",
"axes":[
{"request":"short human-like phrasing of the axis",
"observation":"visible evidence across the images",
"why_free":"why the base prompt leaves this open",
"tpips_factor":"short noun phrase, subject + attribute",
"mapping_status":"faithful",
"constraints":[]}
]}
status is one of ok, no variation, or unassessable; axes is empty unless status = "ok". mapping status is
faithful or needs review, depending on whether the short tpips factor name faithfully captures the request.

Prompt Template: Generation Policy
You are given an image-generation prompt and a diversity axis.
Base prompt:
{base prompt}
Axis:
{axis}
Write exactly K image-generation prompts which vary the main prompt along the given axis.
RULES, in order of importance:
1. THE BASE PROMPT’S CHOICES ARE CONSTRAINTS, NOT VARIABLES. Anything it states
explicitly must survive in every prompt: every subject, its count, its kind, and every attribute it
names. If the base prompt says “two men”, every prompt says two men — not a woman, not three
men, not a crowd.
2. WHERE THE BASE PROMPT ALREADY FIXES SOMETHING, VARY WITHIN IT, NEVER
AWAY FROM IT. The axis can only open up what the prompt left open. Contradicting a stated
detail is the single worst thing you can do here.
3. Vary ONLY the given axis, and together cover clearly distinct values of it.
4. KEEP EACH PROMPT UNDER c WORDS. A short prompt keeps the renderer on the base
prompt; every extra description competes with it and pulls the image away from what was asked.
Add the axis change and stop.
5. Hold everything else as close to the base prompt as you can — ideally reuse its exact wording and
only substitute the part the axis changes.
Output exactly K prompts, each wrapped in <prompt></prompt> tags, and nothing else.
Row variants.
• Word cap (Rule 4). c = |p| + 20, where |p| is the number of words in the base prompt, for every
T2I model.
• overall rows. The opening line becomes “You are given an image-generation prompt and a
request for variety,” the axis line reads Axis:
overall, and the task asks for K prompts “as
different from one another as the base prompt allows,” noting that overall names no single
dimension to sweep. Rule 2’s second sentence becomes “A prompt free to differ everywhere else
is still not free to contradict a stated detail, and doing so is the single worst thing you can do
here.” Rule 3 is replaced by: “THE K PROMPTS MUST NOT COLLAPSE, AND MUST NOT ALL
DIFFER IN THE SAME ONE WAY. Writing the same prompt K times is the obvious failure; K
prompts that differ only in, say, the time of day is the one to actually watch for, because it looks
like an answer. Spend more than one degree of freedom.” Rule 4 ends “Add what you are changing
and stop,” and Rule 5 becomes: “Keep every detail the base prompt states, in its own wording.
Everything it does not state is yours to change.”
