## 摘要
智能体式图像编辑器将复杂请求分解为多个步骤，但当某一步失败时，它们大多使用同样狭窄的工具集重试，并由一个直接凭肉眼为每个输出打分的评判器进行评判。我们认为，此类智能体受限于两个空间：智能体能做什么的动作空间，以及其评判器能看到什么的观测空间。在我们专家标注的基准上，通用编辑器在超过40%的情况下无法产生可用结果，且没有评判器能在所有编辑类型上保持可靠。我们提出 EditAgent，扩展了这两个空间。它将每个步骤路由到通用编辑器和专用方法，并为每个候选结果附加验证记录。借助这些记录，现成的 VLM 评判器优于微调后的奖励模型。候选结果并行生成，并在一次列表式调用中评判：在已决比较中，专家在78.5%的情况下更喜欢这种方法而非顺序细化，且评判调用次数不超过一半。EditAgent 在三个基准上提升了两个开放权重编辑器，并可作为训练更强编辑器的数据引擎。

## Abstract
Agentic image editors decompose complex requests into steps, but when a step fails, they mostly retry with the same narrow set of tools and a judge that scores each output by eye directly. We argue that such agents are bounded by two spaces: the action space of what the agent can do, and the observation space of what its judge can see. On our expert-annotated benchmark, a general-purpose editor yields no usable result in over 40% of the cases, and no judge is reliable across edit types. We present EditAgent, which expands both spaces. It routes each step to general editors and specialized methods, and attaches to each candidate a verification record. With these records, off-the-shelf VLM judges outperform finetuned reward models. Candidates are generated in parallel and judged in one listwise call: experts prefer this to sequential refinement in 78.5% of decided comparisons, at no more than half the judge calls. EditAgent improves two open-weight editors on three benchmarks and serves as a data engine for training stronger editors.

## 1. 核心问题与研究动机

- **背景**：指令式图像编辑模型已能完成单条指令的编辑，但真实请求常是复合的（如"把我移到画面左侧、拉宽镜头露出海滩、去掉身后行人、调成日落"）。智能体式编辑器通过"规划—编辑—评判"循环把请求拆成步骤，但**某一步失败时，它们基本只是用同一套窄工具重试**。
- **核心论点**：智能体式编辑受限于两个空间——
  - **动作空间（action space）**：智能体能做什么；
  - **观测空间（observation space）**：其评判器能看到什么。
- **诊断性发现**（基于作者构建的专家标注基准，600 组、30 种编辑类型、5 名 Photoshop 专业修图师盲标）：
  - 通用编辑器（FLUX.2-klein-9B）在 **42.7%** 的集合中没有任何可用结果；专用方法可挽回其中 **175/256** 个失败；
  - 失败高度集中于几何（66.7% 仅专用方法可用）、增强（72.5%）、光度类编辑；
  - **没有任何评判器在所有编辑组上都最准**：EditScore-72B 总体最好但仅在 Scene 组最好；CLIP-I 在光度/增强组最好却在风格/几何组接近随机；Qwen3.8-27B 在三个组最准，但在光度组仅比随机高 5.2 点。
- **结论性提问**：编辑智能体失败时，"再试一次"并非所需；它需要**换工具**并**看得更细**。

## 2. 方法论

### 2.1 核心思想
同时扩展智能体的**动作空间**（路由到通用编辑器 + 专用方法）与评判器的**观测空间**（为每个候选附加"验证记录" evidence），并以**并行候选生成 + 单次 listwise 评判**把二者耦合起来。

### 2.2 整体流程（Planner → Analyzer → Router → 并行生成 → Judge → 接受/重试）
- **Planner**：把用户请求分解为有序步骤，每步含操作类型（recolor / remove / replace / add / move / scale_subject / relight / harmonize / filter / zoom_in / zoom_out / camera_view / flip / rotate / generic）、目标指代表达、需保护区域（protect_desc）、派生约束（derived_constraints）与参数；并规定"结构编辑先于外观编辑、局部编辑先于全帧编辑"的排序规则。
- **Analyzer**：把步骤改写为可执行指令（说明"改什么、保什么"），给出最多 4 条可检验的验收标准、候选数量（1–3）与方法参数；重试时依据评判反馈修订，且不得重复已失败策略。
- **Grounder**：VLM 输出框（坐标归一化到 [0,1000]），SAM 2.1 细化成掩码，再由 VLM 复核掩码（最多 2 次）。
- **Router**：确定性代码，按操作类型把步骤映射到方法池（Tab. S4）；**每个掩码方法都与通用编辑器同场竞争**，掩码不完美时评判器可回退到通用编辑器。
- **并行生成**：所有被选方法从**同一步的源图**各自生成至少一个候选（每次尝试最多 3 个），而非在上一轮输出上继续编辑。
- **Judge**：现成 VLM（Qwen3.8-27B）在**一次调用**中读取源图、全部候选及其验证记录（随机打乱顺序），对每个候选给出 note / pass / score(1–10) / best_trial / ranking；仅评判器可接受候选。
- **控制流**：每步最多 3 次尝试、每轮最多 2 次重规划、每轮 1 次修复；会话以**版本图**存储，已接受状态不可修改，用户纠正从父节点分支。

### 2.3 扩展动作空间（能力池）
通用编辑器之外包含：掩码局部编辑与重着色（SAM 2.1 掩码 + 羽化/膨胀）、OSOR 对象移除、专用对象移动模型、主体缩放（ViTMatte 抠图 + 重采样 + 原地修复 + 接触阴影 + 色彩和谐）、全局/局部光度算子（CIELAB 闭式亮度/对比度/饱和度/色温 + 反锐化掩模）、25 种确定性风格滤镜、神经风格迁移（VGG-19）、多参考编辑器、翻转与精确旋转（90° 倍数为精确像素置换）、水平校正旋转工具（Hough 长线估计角度 + FLUX.1-Fill 补边）、放大裁剪（Swin2SR 超分）、画布扩展（外扩 + 生成补边）。

### 2.4 扩展观测空间（验证记录）
每个候选附带由代码从源图与候选像素**以相同方式**计算、且**不暴露方法名**的记录：
- **可见变化比例**（CIELAB ΔE > 8 的像素占比，细节类编辑不做模糊）；
- **变化图**（统一尺度的 ΔE 亮度图，只定位变化，不用于判色/判真实感）；
- **局部特写**（BEFORE | AFTER，同一位置同一尺度，高度 448 px）；
- **按操作选取的测量**：亮度/对比度/饱和度/高光裁剪/暗部压死/色偏、锐度与噪声比、结构 SSIM、方向相关性、构图放大倍率与匹配分数；
- **VERIFIED / TO JUDGE 两栏**：代码或构造可保证的性质（如掩码外像素不变、翻转的精确像素置换）与仍需视觉判断的性质。**未通过代码检查的候选在评判前直接剔除。**

### 2.5 多轮一致性：历史检查
每轮结束后，把原图、此前各轮结果、当前图、局部 THEN | NOW 特写与携带约束交给 VLM，逐轮判断"是否仍成立 / 是否被后续请求合理取代（superseded）"，给出分数与置信度；置信度 ≥ 0.4 的违反触发一次修复轮，且修复结果须被步骤评判器接受才采纳。

### 2.6 关键实证支撑（方法设计的依据）
- **更多采样不等于更大动作空间**：通用编辑器多采样 + 同一评判器交付的可用率为 45.2%，加入专用方法后为 68.2%；在恰好一个交付可用的 296 组中，217 组来自含专用方法的池。
- **并行搜索优于顺序精修**：144 个 Complex-Edit 样本盲测，专家在 102:28（14 平）中偏好并行搜索，即 **78.5%** 的已决比较，且 VLM 调用 ≤ 2 次 vs 顺序精修的 4 次。原因是编辑必须忠于源图，顺序精修会累积误差。
- **比较式评判 + 证据**：在 EditReward-Bench 上，listwise 使 Qwen3.5-27B / Qwen3.8-27B / Gemma-4-31B 从 71.7/72.1/73.8 提升到 85.2/85.9/86.1（+12~14 点），超过 EditScore-72B 四路集成的 76.3%。
