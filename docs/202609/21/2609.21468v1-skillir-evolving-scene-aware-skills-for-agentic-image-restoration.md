## 摘要
本文研究智能体图像复原，其中多模态智能体协同调用专门的复原工具，以恢复受复杂退化影响的图像。现有复原智能体通常从原始退化图像中推导出完整的工具使用计划，或检索先前成功的轨迹，难以为使单个动作适应不断演变的中间复原状态提供充分支持。我们发现，被接受的工具执行会改变残余退化状态，从而影响后续工具的适用性。为解决这一问题，我们提出 SkillIR，一个技能引导框架，它将复原经验表示为以退化为中心的动作证据，而非完整的工具使用轨迹。SkillIR 将依赖上下文的动作结果整合为场景感知的复原技能，这些技能刻画了适用条件、预期效果和可归因的失败案例。检索到的技能并不规定完整的复原计划，而是在经过验证的残余状态循环中一次引导一个有界动作：每个工具输出都被视为候选，只有在转移验证后才被提交，随后重新评估当前活跃的残余退化。每次推演后，所得证据用于创建、细化或修补动态技能，使积累的复原经验能够改进后续输入的决策。在合成与真实世界多退化数据集上的实验表明，SkillIR 提升了复原质量，并实现了更可靠、更有效的工具使用。

## Abstract
This paper studies agentic image restoration, in which multimodal agents coordinate specialized restoration tools to recover images affected by complex degradations. Existing restoration agents often derive complete tool-use plans from the original degraded image or retrieve previously successful trajectories, providing limited support for adapting individual actions to evolving intermediate restoration states. We find that accepted tool executions can change the residual degradation state and, consequently, the applicability of subsequent tools. To address this issue, we propose SkillIR, a skill-guided framework that represents restoration experience as degradation-centered action evidence rather than complete tool-use trajectories. SkillIR consolidates context-dependent action outcomes into scene-aware restoration skills that characterize applicable conditions, expected effects, and attributable failure cases. Instead of prescribing a complete restoration plan, the retrieved skills guide one bounded action at a time within a verified residual-state loop: each tool output is treated as a candidate, committed only after transition verification, and followed by reassessment of the active residual degradations. After each rollout, the resulting evidence is used to create, refine, or patch dynamic skills, enabling accumulated restoration experience to improve decision-making for subsequent inputs. Experiments on synthetic and real-world multi-degradation datasets demonstrate that SkillIR improves restoration quality and enables more reliable and effective tool use.

- **现有方法的两种范式及其局限**：
  - **策略学习类**（强化学习/智能体后训练）：把工具选择与排序内化到参数中，推理高效，但新增工具或退化类型通常需要额外优化。
  - **免训练类**（执行记录、反思、轨迹记忆）：灵活性高，但经验通常以**完整计划或完整轨迹**的形式保留，粒度较粗。
- **核心痛点**：被接受的工具执行会改变**残余退化状态**，从而改变后续工具的适用性。因此：
  - 一次成功动作可能只是**缓解**而非**消除**当前退化，还可能影响共存退化或已复原内容（跨退化副作用）。
  - 过早切换退化会留下未解决问题；重复已不适用的动作会引入伪影或破坏细节。
  - 仅依据原始退化图像一次性推导完整计划，或复用历史完整轨迹，难以适配不断演变的中间状态。
- **整体含义**：论文主张把复原经验表示为**以退化为中心的动作证据**（而非完整轨迹），使智能体能够基于当前残余状态逐步、可验证地决策，并让经验跨样本持续积累。

## 2. 方法论

### 2.1 核心思想
- 提出 **SkillIR** 框架，包含两个互补组件：
  1. **场景感知技能构建与演化**：把已验证的工具使用轨迹抽象为退化为中心的复原技能与失败教训。
  2. **技能引导的验证复原**：在“验证残余状态循环”中，每次只引导**一个有界动作**（单次专家工具调用），经转移验证后才提交，并重新感知残余退化。

### 2.2 关键技术细节

- **退化为中心的轨迹分解（Degradation-Centered Trajectory Decomposition）**
  - 将完整轨迹切分为若干 **episode**：每个 episode 是围绕某一退化处理的极大连续子序列，始于该退化被选中，止于其被解决、暂缓或切换到其他退化；同一退化再次被处理则开启新 episode。
  - 保留对应的 **Progress / Resolved / Rejected** 转移，使动作结果可归因到具体复原目标。

- **复原技能构建（Restoration Skill Construction）**
  - 每个技能包含：适用条件（场景上下文、正在处理的退化、共存的残余退化）、可允许动作与参数边界、预期复原效果、验证标准。
  - 使用固定模型与解码配置的标准 MLLM 提示词，将 episode 证据转为结构化表示。

- **失败即教训（Failures as Lessons）**
  - 被拒绝的转移在可可靠归因时保留为失败教训，记录复原上下文、尝试动作、失败模式（去除不足、结构损伤、伪影引入、工具–上下文不匹配），并给出排除条件或回退指导。

- **技能维护与演化（Skill Maintenance and Evolution）**
  - Skill Manager 通过四种操作更新：**Create**（新建动态技能）、**Merge**（合并兼容的 Progress/Resolved 证据，细化适用条件与约束）、**Patch**（把可归因的 Rejected 证据作为失败教训挂载，更新排除/回退规则）、**Reject**（丢弃不完整、不一致或验证不足的证据）。
  - **静态技能**保持不变；**动态技能**仅通过验证过的更新演化。
  - 技能库在单张图像复原过程中固定，**仅在 rollout 完成后更新**，因此当前图像的经验只影响后续输入；更新仅依赖工具使用观察与转移验证结果，不使用参考图或真值退化标签。

- **技能引导的验证复原循环**
  - 复原上下文定义为 `ct = (s, dt, zt, Ht)`：`s` 为场景上下文，`dt` 为当前选中的活跃退化，`zt` 为活跃残余退化及其严重度/置信度，`Ht` 为当前 rollout 内的动作尝试与验证结果历史。
  - **场景感知技能检索**：技能库 `L(n) = Lsta ∪ Ldyn,(n)`；MLLM 依据场景、目标退化、残余退化与历史结果对技能排序，取 **top-k** 作为 `Kt`；若无足够兼容技能，则回退到受约束的直接规划（需满足失败教训、本 rollout 已拒绝动作与执行约束）。
  - **有界动作选择**：每步只选一个专家工具 `ft`，且必须被检索技能支持或来自受限回退，且不被失败教训/已拒绝动作/执行约束排除；当前动作效果被观察后才选下一个。
  - **验证转移评估**：执行得到候选 `Ît+1 = ft(It)`，仅当验证器判定其可靠降低 `dt` 且未在其他区域造成不可接受损伤时才接受；`It+1 = Ît+1`（接受）或 `It+1 = It`（拒绝）。拒绝记为 **Rejected**；接受后重新感知，若 `dt` 仍活跃记为 **Progress**，否则记为 **Resolved**。
  - **残余状态更新与调度**：Rejected 后重新检索并排除该动作；Progress 后 `dt` 仍为目标，若还有可用动作则继续；Resolved 后切换到其他活跃退化；若 `dt` 仍活跃但无可用动作则暂缓，待残余状态变化后再访问。终止条件为无活跃退化可处理或执行预算耗尽，返回最新提交图像。
